# Security reporting and dependency support

Fluent.Pdf is under implementation. There is no production-qualified stable release or currently supported published version. Do not infer support from a source target framework or development artifact.

Use GitHub private vulnerability reporting for this repository when available. Otherwise contact the maintainer through GitHub to agree a private reporting channel before sharing sensitive details. Do not attach customer documents, credentials, private signing keys or working exploit inputs to public issues. A useful report identifies the source revision or exact artifact hash, platform/runtime/provider, affected operation and a minimal original reproduction that contains no private data.

Security fixes and dependency updates require review, explicit affected-component analysis, updated provenance/notices, regression coverage and renewed applicable runtime/RID, resource and fidelity qualification. Known findings and unresolved provenance or licensing gaps block release; they are not waived by a successful vulnerability query. New dependency bytes invalidate previous final-package evidence. Native engines and models remain caller-provisioned until their redistribution and deployment profiles are qualified.

Before the first stable release, publish the supported-version and engine/model lifetime matrix and the maintainer's response/update commitments. No response-time guarantee or unsupported third-party maintenance promise is made by this implementation checkpoint. See [supply-chain inventory](docs/supply-chain.md) and [production gates](docs/production-quality.md).

The [compatibility and maintenance policy](docs/maintenance.md) defines versioning, reviewed migration, affected dependency requalification, evidence retention and authorized rollback/unlisting. Its source drill does not establish a supported release or an approved response commitment.
