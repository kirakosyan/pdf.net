# Independent Open XML source fixture check

This development-only executable uses the published DocumentFormat.OpenXml 3.3.0 validator (MIT license), with exact dependency identities in packages.lock.json. It is outside the product solution and introduces no SDK runtime dependency. It opens only controlled original PPTX/XLSX fixtures read-only, validates against the explicit Office2019 schema/part rules and writes a hashed report, retaining earlier reports by digest. Failures produce a nonzero process exit; success does not qualify complete format/application fidelity or final packages.

Run with `dotnet run --project eng/format-checks/OpenXmlCheck.csproj -- fixture.pptx report.json` after explicitly restoring the tool. The generated data profile uses literal strings, ISO calendar dates, merged ranges and PNG pictures. No imported actions, macros, external media or office applications execute.

The `epubcheck` subdirectory specifies a separate development-only EPUBCheck 5.3.0 resolver (BSD-3-Clause primary artifact). Maven 3.9.9 and OpenJDK 21 are analysis tools. `tool-jars.json` retains every actual transitive JAR digest; `eng/verify-epub-fixtures.py` rejects different/missing/extra validator binaries before running the controlled EPUB files. No JVM/library is added to SDK projects or deployed automatically. Provision the tools explicitly, using the host's configured network proxy for Maven where required. The wrapper retains prior JSON/log reports, checks actual process/report results even under Python `-O` and records the actual Java identity and file hashes. EPUB structural validation does not establish reader/visual/RTL/font/accessibility or final package qualification.

Development-only XPS/OpenXPS checks use a separately built XPS interpreter at version10.05.1, with exact source, binary, build configuration and task-local GNU tool relocation hashes in `ghostxps-reader.json`. Original fractional-page interoperability failures remain recorded separately; integral-unit raster fixtures pass both namespaces. No parser/render implementation was modified or adopted into the SDK. The independent-reader build is AGPL-3.0-or-later and remains an external analysis artifact.

The `ofd-reader` checker uses explicitly resolved reader artifacts at version2.3.7 (Apache-2.0 primary artifact, parent-POM license evidence retained). `tool-jars.json` binds every actual transitive JAR by SHA256; a different/missing/extra binary closure rejects. The original Java checker opens only our controlled PNG/page package with Java headless AWT; it adds no JVM/AWT dependency to the SDK. Raw Maven provisioning metadata/JARs remain outside the repository.

Controlled EPS fixtures use the installed10.05.1 interpreter (AGPL-3.0-or-later); EMF uses installed Inkscape1.4 (GPL-2.0-or-later); escaped ASCII LaTeX uses installed pdfTeX1.40.26 and explicit local TeX Live assets. These are analysis tools, never default SDK processes. Wrappers retain actual versions/binary/fixture/report hashes and archived prior results. Invoice/preflight checks use independent PDF/XML readers and explicitly do not claim full invoice, PDF/A or other standard conformance.
