# Explicit private browser container source host

`ChromiumContainerHost.Open` is an optional source implementation of `IChromiumConnection` for a caller-provisioned local Docker daemon and Linux browser image. It is not a qualified engine distribution. Supply an absolute local CLI path/SHA-256, explicit local Unix socket or supported Windows named pipe, immutable local image ID, protected empty CLI configuration directory and exact caller-reviewed default-deny seccomp file/SHA-256. No runtime pull, executable discovery, environment proxy, account credentials, host mounts or browser binary installation occurs.

Each job receives a unique owned container name/label, offline network namespace, read-only root, nonroot UID/GID 65532, dropped outer capabilities, no-new-privileges, caller-pinned syscall policy, 1 CPU, hard memory with no swap expansion, process/thread ceiling, bounded tmpfs/shared memory and a finite wall deadline. The source bridge checks UID, capabilities, seccomp/no-new-privileges, loopback-only interfaces, read-only root and cgroup-v2 memory/PID values. It retains Chromium's inner sandbox. Both the renderer and CLI controller occupy scoped worker slots; container memory is reserved against the same SDK expanded-byte budget.

Source admission permits 256 MiB–2 GiB memory, 8–512 processes/threads (default 64), and 1 second–10 minutes wall time. The original finite Chromium 155 fixture explicitly requires 512 MiB and 256 tasks; the retained 128-task failure recorded 46 denied allocations and no OOM. This observation is not a universal sizing promise or a weakened production gate. Framed UTF-8 JSON is bounded; stdout/stdin operations are serialized, stderr is drained without retaining payloads, and cancellation/deadline polling stops pending I/O. Only the owned container is removed through an out-of-band command; disposal joins owned transports and releases its reservation. Cleanup failure remains fatal and retains `Fluent.Pdf.Html.OwnedContainer` for reconciliation.

Creation and startup now use separate supervised CLI requests. The host requires a successful bounded exact 64-hex creation acknowledgement before issuing `start --attach --interactive` against that immutable ID. Cancellation or bootstrap failure after acknowledgement removes that ID; a late start cannot recreate a removed container. After acknowledgement, cleanup never substitutes another container that reuses the name. If creation itself is unacknowledged, `Html.HostStartupUnconfirmed` retains the owned name for reconciliation: a late create may still leave a stopped container, and a single absence query cannot prove future absence. No browser start or private document transfer is issued in that uncertain state. Cleanup failures also retain the known ID when available.

Caller cancellation now retains one exception within its operation so bounded owned-resource details survive outer checkpoints. Independent operations do not share that exception. The daemon remains a trusted privileged prerequisite, and protected source/config paths must not change during use. CLI/hash checks are not a race-free loader for attacker-controlled trees. Unacknowledged-create reconciliation, kernel/syscall review, cross-host isolation and startup/cleanup adversarial qualification remain release blockers. No successful source fixture is evidence that those gaps are closed.

`eng/build-browser-container-fixture.ps1 -ProvisionSourceImage` explicitly builds a private local analysis image from an immutable Debian index and signed dated package snapshots. It retains the original source context, image ID, CLI hash, package/version and engine/file inventories. Only the original fixture font is selected. The image is neither pushed nor redistributed. The SDK itself ships no Chromium, Docker, Python or OS binary. All third-party engine/OS licenses, vulnerabilities, ABI and complete dependency closure need separate distribution review.

The task-local source syscall policy is derived from an exact external analysis-policy blob by `eng/prepare-browser-fixture-policy.py`. It requires the original hash and exact Apache-2.0 license, records original/modified hashes and a unified diff, and prominently marks modifications permitting the inner sandbox's user/PID/network namespace creation and chroot. No global daemon/kernel policy is changed. These source-only exceptions are not a reviewed production policy. Raw analysis inputs remain outside Git with retained attribution and limitations.
