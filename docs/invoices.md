# Electronic invoice source gate

`ManagedPdfInvoiceProducer` now prepares the SDK's MINIMUM draft with an explicitly supplied ICC output space, synchronized Info/XMP, the four invoice metadata properties and a PDF/A extension declaration. It verifies exact generated XML/model/associated-file binding and rejects existing XMP rather than replacing it implicitly. It uses the same operation context and private archival rewrite path as `PdfArchival.Convert`; no validator or asset is discovered. `PdfInvoices.Write` still requires explicit complete independent archival and invoice validators. Calling the producer directly returns an unvalidated candidate.

The archival writer permits associated files in its private PDF 1.7 preparation path, as required by PDF/A-3. Ordinary PDF association output retains its PDF 2.0 floor, and unrelated PDF 2.0 features still reject a PDF 1.7 target. Source fixtures now run actual veraPDF 1.28.2 and the explicit exact-edition invoice host described below. Full corpus, isolated-host and final-package qualification remain open; this does not complete #79 or #100.

```csharp
var producer = new ManagedPdfInvoiceProducer(explicitIccSpace, "Explicit output condition");
var identifiedInvoice = invoice.WithSellerRegistration(explicitLegalRegistrationId, "FR");
PdfInvoices.Write(identifiedInvoice, output, body, layout, providers, producer,
    independentArchivalValidator, independentInvoiceValidator, explicitHostBudget);
```

`PdfInvoiceData` is immutable and requires an exact requested version/profile, literal identity/parties, whole-second UTC issue time, explicit currency and midpoint rounding. The bounded source profile accepts1–1000 positive-quantity, nonnegative-price lines with tax percentages; it rounds line net amounts, groups those net amounts by explicit tax rate, then rounds tax once per rate category. `TaxCategories` exposes each rate, taxable sum and rounded tax; `TaxTotal` sums category taxes. Visible line amounts/rates, category breakdowns and CII header totals use that same calculation. EUR/USD/GBP, JPY and BHD have explicit minor-unit exponents. Unknown currencies, negative inputs, excessive precision/magnitude and empty invoices fail. No tax jurisdiction, credit note, discount or prepayment is inferred.

`PdfInvoices.Write` composes human-readable text and escaped CII XML from that single model, with explicit fonts/shaping/page layout. The requested profile is Factur-X1.0.07 MINIMUM; CII contains its literal guideline identity and calendar date, currency and reconciled header totals. The private draft embeds exactly `factur-x.xml`, with a document-level AF entry and Data relationship. The draft is not an invoice compliance result and is never directly published by this API.

Writing requires `WithSellerRegistration` to supply an explicit legal-organization registration identifier and uppercase seller country code. Neither a customer identifier nor a country is inferred. Calculation-only models may omit these values; writing fails with `Invoice.SellerIdentityRequired`. This exact edition limits header monetary amounts to two fractional digits. BHD still calculates at three minor-unit digits, but a header total that cannot be represented exactly at two digits fails with `Invoice.ProfilePrecision`; it is never silently rounded. Independent code-list validation rejects syntactically valid unknown countries.

Publication requires an explicit complete invoice producer, a complete independent PDF/A-3b validator and a separately identified complete invoice validator for the exact edition's schema, business rules, metadata and readable PDF/XML/model reconciliation. The SDK reparses nonempty candidate output and verifies exact associated XML bytes, filename/variant identity, MIME and AF relationship. Both independent results must bind to exact bytes/profile; invoice validation also binds XML and model/settings digests. Incomplete, failed or stale observations cannot expose output. Metadata markers or XML syntax alone are never compliance evidence.

All composition, fonts, layout, XML, attachment, engine, hashing and validation phases share one operation context with bounded staging and expiring provider leases. Caller streams/providers remain caller-owned. Backend failures redact payloads and preserve latched limits/cancellation/losses. No runtime schema/font/package/network discovery occurs.

The optional Compliance assembly's `FacturX107MinimumReportValidator` accepts an explicit supervised runner. It captures exact PDF/XML inputs, serializes the immutable model with a fresh nonce, and requires an exact engine/rule-bundle/request/input/model-bound report. All five phases—schema, business rules, metadata, independent arithmetic/model and readable painting—must be present, complete and compliant before output. Missing/duplicate phases, stale reports, DTDs, private finding payloads and contradictory counts/flags reject. Stable finding codes are available on failure in the string `Fluent.Pdf.InvoiceFindings` exception data. This bridge verifies report structure and binding; the caller remains responsible for an independent truthful host.

`eng/build-invoice-fixture.ps1` explicitly provisions development-only assets from the pinned catalog `eng/format-checks/invoice-107.json`. The original Java host runs every XSD and Schematron rule from the exact Factur-X1.0.07 MINIMUM bundle (54 assertions and 11 reports), using Saxon and PDFBox 3.0.8 from the hash-pinned analysis JAR. It does not use the JAR's newer default invoice rules. Two declared upstream schema filename aliases resolve to the same unmodified pinned bytes; all other schema/URI resolution is denied. The host independently recalculates currency/rounding/category arithmetic, matches header identities and amounts, inspects XMP/AF/embedded XML, and checks readable text against the private model.

Readable reconciliation has an explicit conservative profile: black, opaque, embedded Unicode-mapped TrueType vector text, with no other painting, overlapping glyphs, annotations, optional content or active forms. It checks actual glyph outlines against clipping and embedded-font Unicode maps, rather than accepting extracted text alone. Invisible and point-scale clipped text fail. Other painting/fonts return an incomplete `Invoice.PaintProfile` observation, preserving the gate. A retained 0.0001-point numerical tolerance covers PDFBox float conversion; production geometry thresholds are unchanged. This does not establish arbitrary graphical invoice readability, human review, legal/tax correctness, complete multilingual fidelity or general font authenticity.

The real-engine source tests cover EUR/JPY/representable BHD, both midpoint policies, compiled C#/VB consumers, invalid country rules, tampered bindings, invisible/clipped painting and unchanged destinations on failure. Separate fabricated report-protocol fixtures test only the bridge boundary. The source host reserves 512 MiB under the shared context, limits JVM heap/direct memory and transport/report sizes, uses a finite deadline and joins owned processes/transports. Its Java executable is an explicit source prerequisite; SDK code installs or starts nothing. Complete supported-host isolation, corpus and final-package qualification remain mandatory for FP-070, which stays Planned.

The older `invoice-schema.json` structural regression remains historical evidence and does not qualify the requested edition. The new exact-edition host has a separate catalog and reports. Raw schemas/JARs stay outside tracked source, with their upstream licenses/notices retained alongside the analysis assets; nothing is added to SDK packages.
