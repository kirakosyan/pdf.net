# Explicit structural repair source profile

FP-006 adds `PdfRepair.Recover`, `PdfStructuralValidation.Inspect`, exact stream-length authority, active-object selection, an immutable source/output result and a versioned machine-readable XML ledger. These are source implementations; full recovery profiles, the damaged corpus and production qualification remain pending. NuGet packing and publication stay blocked.

Normal `PdfSyntax.Read`, `Pdf.Open` and structural inspection never invoke repair. Syntax failures remain fatal in strict and permissive modes. `Recover` is a separate operation that snapshots the exact caller input, reconstructs one classic-index revision in private staging, runs the ordinary strict reader on the complete result and copies output only after structural post-validation. It never catches a latched parse failure and turns it into success.

The scanner parses unique indirect object frames and skips literal strings, comments and raw stream bytes using lexical boundaries. It never searches a payload for `endstream` or an apparent object header. A valid direct length or an already recovered scalar reference establishes a stream extent. Missing, invalid, cyclic or forward unresolved lengths require a caller-supplied `PdfRepairStreamLength`; its exact extent must still terminate at valid stream/object framing. Unused overrides fail. Encoded payload bytes remain exact; structural recovery does not claim codec, image or page-content reconstruction.

Classic xref subsection identities, generations and active/free status provide object authority even when offsets/free chains are damaged. Offsets are rebuilt from actual frames. A free, unindexed or nonselected physical body is excluded and recorded. No source-position or highest-generation heuristic resurrects objects. Without recoverable status rows, `activeObjects` must supply a complete explicit identity inventory. An indexed/selected identity without its exact physical generation fails. Duplicate physical definitions, multiple revisions/trailers, hybrid/compressed indexes, object streams and encrypted recovery require separately validated profiles and currently fail with actionable diagnostics.

The recovered trailer retains its entries, removes obsolete index-layout keys and receives a rebuilt Size/root/index/footer. A missing root can use the sole active Catalog; multiple choices require explicit `root` authority. A selected root must actually be an active Catalog. Missing exact reference targets block recovery by default. Explicitly retaining PDF null-reference semantics records each observed unresolved reference. Structural inspection distinguishes an existing indirect null value from a missing identity, handles graph cycles and also checks references within unreachable objects.

`orphans: Preserve` identifies and retains indexed objects unreachable from the recovered trailer. `Discard` identifies every removed object and reports an omission; strict processing rejects that loss and permissive processing retains its diagnostic. All physical signature bodies require explicit invalidation permission before recovery, including inactive or orphan signatures. An authorized rewrite is recorded; no cryptographic signature validity or certification permission is inferred.

`PdfRepairResult` exposes SHA-256 digests and read-only `OpenOriginalStream` / `OpenRepairedStream` views independent of caller stream lifetimes. Its ledger records framed/reindexed objects, excluded physical bodies, orphan decisions, stream overrides, root authority, index/footer reconstruction, signature invalidation and strict post-validation. `WriteLedger` writes UTF-8 XML with version and both digests through a separate explicit budgeted serialization operation. Ledger messages contain no imported document strings or payload snippets.

One mandatory context covers source capture, scanning, reference/orphan analysis, staging, strict output parsing, hashes and final copy. Allocations and scoped depth use shared budgets; loops poll cancellation. Input/output are distinct borrowed streams at their current positions and remain caller-owned. A final stream I/O failure can leave partial bytes. No file-path repair API or SDK temporary-file path is exposed by this profile.

Original damaged fixtures exercise wrong offsets, exact stream overrides, misleading payload/header text, excluded freed bodies, root inference, active inventory authority, missing EOF, null references, orphan/signature policies and unsafe profiles. Two unrelated readers check recovered page/text semantics and ledger/source/output digests. These fixtures do not qualify arbitrary damaged documents. Complete revision/hybrid/compressed/encrypted recovery, additional stream/codec/content repair, full ambiguity/fuzz/resource/concurrency/endurance campaigns, actual minimum runtimes, exact final-package consumers and every production gate remain mandatory.
