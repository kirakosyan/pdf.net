# Unicode and shaping

FP-009 has original managed Unicode analysis and text composition in source, with explicit optional shaping providers. The core has no native font, platform, browser or GUI dependency. `Fluent.Pdf.Text` is an optional, non-packable broker targeting net472, netstandard2.0, net8.0 and net10.0. Source evidence does not qualify the complete SDK or authorize NuGet candidate creation/publication.

`PdfUnicode.Analyze` preserves well-formed logical UTF-16 without normalization. It returns scalar provenance, extended grapheme boundaries, paragraph base levels, resolved bidi levels and visual scalar indices. Original UAX #9 and UAX #29 algorithms use pinned Unicode 18.0.0 snapshot data rather than runtime Unicode tables. The snapshot commit, input/data hashes and Unicode license are retained under `third-party/unicode`. The offline generator accepts a caller-provisioned normative-data directory. The official 490,846 bidi class vectors, 91,707 bidi character vectors and 853 grapheme vectors are exercised without exclusions. Segment separators require an explicit layout/tab-stop policy and fail at this shaping boundary. Visual order excludes X9 formatting characters; logical text retains them. Paragraph analysis is distinct from line breaking; layout must apply line-specific bidi rules when it wraps.

`PdfText.Shape` takes explicit immutable fonts, a provider registry and `PdfTextOptions`. It selects the first supplied font covering each complete grapheme, itemizes by script, direction, font and paragraph, supplies full logical context to the shaper, then validates and copies its glyph/cluster output. Missing cluster coverage fails with `Text.MissingClusterFont`. No installed-font discovery or silent font substitution occurs. Runs contain exact font identities, original UTF-16 cluster offsets, design-unit advances and placement offsets. Feature ranges use original UTF-16 offsets; language and OpenType features are explicit. Fonts with different units per em keep their own metrics.

`PdfSimpleTextShaper` explicitly supports scalar-only horizontal Latin, Greek and Cyrillic requests. It rejects combining marks, complex scripts, vertical writing and feature overrides with `Text.ComplexShaperRequired`; it makes no OpenType shaping claim. Complex shaping requires an explicitly registered `IPdfTextShaper`.

`IsolatedTextShaper` uses a fresh original C bridge and pinned HarfBuzz 14.2.1 assets from native-asset packages 14.2.1.301. It requires a caller-provisioned `NativeWorkerOptions` deployment with exact ABI `fluent-pdf-text-1`, engine version and every asset's length/SHA-256. It copies original static OpenType/collection bytes through `IPdfFontShapingSource`; embedding conversion is not used as shaping input. Standalone Type 1/CFF, authored Type 3, variable instances and other source profiles require explicit compatible providers. Original-source copying grants no embedding permission. Font embedding rights are checked when constructing PDF resources.

The bridge accepts bounded font/text/feature envelopes and emits fixed-width glyph records. The parent reserves the complete configured native memory envelope before launch. OS isolation, process memory/time limits, crash recovery and private jobs come from the mandatory worker boundary; there is no unsafe fallback. Configure a shared expanded-byte budget large enough for the cumulative per-run native envelopes plus managed copies. Windows x64/ARM64, Linux x64/ARM64 and macOS x64/ARM64 are the source integration targets; minimum OS/libc/C++ runtime and final deployment qualification remain pending. Linux keeps the asset's exact soname `libHarfBuzzSharp.so.0.61421.0`. macOS universal inputs are thinned, assigned a private install identity and ad-hoc signed; original/derived digests are inventoried. Build-time restoration is explicit; ordinary processing never downloads an engine or font. Package hashes, supplied notices and derivation policy are under `third-party/text`.

```csharp
var providers = new PdfProviderRegistry(new IsolatedTextShaper(explicitWorkerOptions));
var policy = new PdfOperationPolicy(limits: new PdfResourceLimits(
    maximumExpandedBytes: 1073741824));
var shaped = PdfText.Shape("office مرحبا", new PdfFontFallback(latin, arabic),
    providers, policy: policy);
var drawing = PdfTextDrawing.Create(shaped, 20, 100, 24);
foreach (var binding in drawing.Fonts)
    document.Pages[0].SetFont(binding.Key, binding.Value);
document.Pages[0].Content = drawing.Content;
```

`PdfTextDrawing` eagerly embeds used glyphs and emits explicit glyph matrices in PDF user coordinates. Paragraphs advance by the requested line height; horizontal and top-to-bottom geometry use actual shaped positions. Its horizontal CID encoding avoids applying vertical origins twice. ToUnicode records logical cluster text, including ligatures, and a surrounding `ActualText` span carries unchanged complete logical Unicode in reading order. These spans do not replace the separate tagged-PDF accessibility requirement. Named font resources remain explicit for page/canvas composition. Prefix collisions and overlay composition belong to that composition boundary. Standard/simple font encoding capacity and the 512-unit mapping limit fail explicitly rather than truncating text.

Source checks cover official Unicode conformance, Arabic/Indic joining, ligatures, marks, vertical CJK, feature overrides, mixed fallback, exact positions, logical text, malformed provider results, cancellation, budget preflight, ownership and independent jobs. Licensed renamed Noto subsets and eight known-answer vectors retain provenance; expected glyphs/positions come from independent Python calls to the pinned public HarfBuzz C API. A direct bridge development probe checks IPC mapping separately from isolated CI execution. Independent development checks compare eight PDF drawings with separately authored reference PDFs: exact glyph matrices/logical ActualText and 921,600 raster pixels with zero differences. Extractor heuristics differ: Poppler emits Arabic display-order text with bidi controls; some readers insert spaces/newlines into individually positioned Indic/vertical glyphs. These observations are retained as copy/search qualification limits. Complete multilingual visual/copy/search/accessibility corpus, minimum runtimes, final packages, dependency/security review, fuzzing and endurance remain mandatory production qualification work. Publishing stays blocked.
