# Preflight, explicit remediation and audit source profile

`PdfPreflight.Inspect` captures exact bounded PDF bytes and passively reports default-policy blocked actions/opaque active content, unembedded font declarations, absent Type0 Unicode maps, invalid image dimensions and signature presence. Findings have stable codes and physical object/key provenance. Available capabilities come only from the caller's explicit registry. No font/image payload or action executes, no input byte changes and `ConformanceValidated` remains false. Complete independent standards checks use their separate explicit validator APIs.

`PdfRemediationPlan` binds the exact input SHA256 and selects only an implemented applicable fix. The current source fix, `RemoveBlockedActions`, removes all actions/opaque content blocked by the documented default action-retention policy, including unattached active objects. It preserves allowed local navigation and absolute HTTP/HTTPS links. It does not infer content/font repairs. The plan records its loss; applying it needs permissive policy. Full rewriting of signature-bearing sources needs additional explicit invalidation authority.

`Apply` and `ApplyFile` reject stale input before editing, modify a private graph, stage a complete rewrite, reparse the written bytes, check page/geometry retention and require the selected blocked-action findings to be absent. Other unresolved font/image/standard findings remain in the after report. Failure or cancellation leaves the destination untouched before stream copying; file output uses atomic replacement. The original input is unchanged. Action removal/full rewrite is not secure erasure; source payloads or metadata outside the selected fix may remain.

Schema1 JSON reports and audits contain exact before/after hashes, stable findings, explicit fix codes, affected physical locations and loss descriptions. Capture, graph traversal, mutation, rewrite, post-inspection and audit encoding use shared bounded operation contexts; borrowed streams remain caller-owned. Input/candidate limits are64 MiB, finding inventories10000 and JSON staging8 MiB.

Fault-seeded tests prove read-only inspection, exact source binding, default strict rejection, stale plans, unresolved findings, post-write checks, JSON/provenance/hash consistency, cancellation/budgets and atomic destination retention. Complete capability/conformance aggregation, broader font/image/color/security repairs, semantic preservation, independent validators/corpus and supported-host/package production qualification remain mandatory for FP-071, which stays Planned.
