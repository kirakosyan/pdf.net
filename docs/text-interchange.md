# PDF text and Markdown interchange

`PdfTextInterchange` exports UTF8 plain text, escaped CommonMark with the pipe-table extension, or a deterministic ZIP containing `document.md` and generated PNG page images. The optional Formats assembly uses the managed extraction pipeline; images require an explicitly supplied renderer. No link is fetched, no document action is run and no asset is written to an ambient path.

Supply the lowercase SHA-256 of the exact PDF bytes at the input stream's current position and an ordered block plan. A mismatch rejects before projection. Each block selects a zero-based page, explicit raw/grouped/layout text order and a caller-assigned paragraph, heading, flat list item, code, link, table or whole-page image role. Repeated pages/ranges are intentional; plan order is reading order. Optional ranges address extracted raw character indices and counts, not UTF16 positions, and require raw order. Unicode clusters remain whole. Grouped/layout order is geometric inference, not verified tagged reading order. Raw ranges do not apply ActualText replacements as a semantic reconstruction step.

The emitted header retains source SHA-256; each block retains its index, page, order, role and raw range or whole-page selection. Roles are explicitly caller-assigned, and grouping is explicitly inferred. All projections report `TextInterchange.Reconstruction` and require permissive loss authority. Original geometry, complete graphics, navigation and verified source accessibility semantics are not retained. Unicode source mappings do not prove linguistic accuracy. A scanned page does not automatically trigger OCR.

Text is escaped so that source punctuation, HTML, Markdown links and list markers stay literal. Fenced code chooses a delimiter longer than every source backtick run. HTTPS links are caller-supplied, without credentials, whitespace or markup; other schemes reject. Headings and link labels require a single line. CR line endings and invalid XML1.0 Unicode scalar text reject rather than silently normalize. Plain text retains literal characters and includes source/block references; it is not an interchange CSV format.

Tables use an explicit ruled/borderless inference profile and optional displayed region. Unit cell spans are required; merged cells reject. The caller may declare one leading header row. Otherwise generated `Column N` headings precede all source data rows. Pipe characters and markup in cells remain literal; embedded LF uses an entity. Multi-page joins and multiple header rows reject. Table inference remains uncalibrated; complete semantic table reconstruction is pending.

Images require bundle mode and explicit whole-page rendering options. Names are generated flat ASCII `page-N.png` values from block order, never source text or caller paths. They are raster page appearances with generic page labels, not extracted original image assets or recovered alternative descriptions. The bundle is staged as one output, avoiding partial multi-file publication. Assets remain subject to renderer/pixel/expanded-byte policies and the archive limits.

The implementation captures at most64MiB source, selects at most4,095 blocks from at most10,000 pages and stages at most16MiB document text. Each PNG is at most16MiB; aggregate ZIP part expansion and archive output are bounded at64MiB. Every phase shares operation budgets and cancellation. Streams stay caller-owned; failed validation leaves the destination stream untouched, while failures during its final copy may leave a partial stream write. `WriteFile` uses atomic replacement after complete staging.

C#/VB `ExportMarkdown` examples accept the exact digest and explicit page. Source tests cover unsafe text/links, Unicode mappings, raw-range order, caller roles, table headers/spans, generated image names, deterministic bundles, cancellation, bounded output and atomic preservation. `eng/verify-text-interchange.py --independent-parser` uses task-local Markdown-it-py and Pillow to inspect original emitted fixtures. This is a finite source profile: automatic tagged semantic reconstruction, nested lists, comprehensive source links/images, complex multi-column reading-order quality, large real corpora, every actual runtime and final-package qualification remain mandatory.
