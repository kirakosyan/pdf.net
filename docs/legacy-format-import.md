# DjVu and CDR import host boundary

FP-107 provides `PdfLegacyImport.Read` in the optional Formats assembly. It integrates an explicitly supplied `IPdfIsolatedLegacyImporter`; it does not bundle a DjVu/CDR decoder or qualify any source format version. The built-in supported-version list is empty. A caller host must document its exact version, compression, external-reference, page, color and font profile and reject any source outside it.

`PdfLegacyImportOptions` identifies DjVu or CDR and a bounded literal version/profile name. It limits source capture (default 16 MiB, maximum 64 MiB), staged PDF (maximum 64 MiB) and output pages (default 1,000, maximum 10,000). Missing host/profile fails before reading the borrowed stream. The host receives captured source and private output through expiring directional leases under the same mandatory operation context. All output is reparsed before a document is returned; empty/invalid/excess-page output rejects. The caller retains input and host ownership. No partial document is returned on failure.

The host reports `UnsupportedVersion`, `MissingCodec`, `MissingFont`, `UnsupportedRecord` or `DamagedInput`; even a valid staged PDF is discarded for these outcomes. Unknown outcomes reject. Ordinary host exceptions are sanitized. Latched resource/cancellation failures remain observable. Every fidelity loss must be reported through the context; strict policy rejects it. The SDK never manufactures an empty page to conceal a failed decode.

The adapter is trusted code. Its interface is not an OS sandbox: native decoding must run in a separately qualified pinned offline host with finite memory/CPU/time/output, no source actions, ambient files/network, automatic linked-document resolution, runtime codec/font downloads or inherited credentials. Charge allocations before use and acquire actual worker scopes. DjVu indirect documents and CDR external assets require an explicit bounded asset model before a host may support them; this source wrapper supplies none. Use [native worker guidance](native-deployment.md) and retain independent isolation evidence for each exact engine/RID.

The source tests use an original fixture host that returns an independently generated PDF. They test integration, rejection, ownership and budgets only. They do not decode DjVu/CDR input. Actual decoder implementation, versioned format corpora, independent readers, damaged-stream/font fidelity, sandbox, actual minimum runtimes and final-package consumers remain mandatory. The requirement stays planned/open; see [source evidence](evidence/FP-107-source.json).
