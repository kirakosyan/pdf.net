# Explicit local OCR

FP-074 has a source-validation profile. Complete real-engine/model/RID integration, supported-language CER/WER, cancellation/allocation/handle/endurance/security workloads, minimum runtimes, exact final packages and every production gate remain mandatory. SDK candidate creation and NuGet publishing remain blocked.

PdfOcrRaster.Read captures an explicitly described Gray8, RGB24 or BGRA32 raster at the borrowed current stream position. Dimensions, stride, DPI72–600 and a finite byte ceiling are explicit. It reads exactly height*stride bytes and one EOF probe; truncation and trailing bytes reject. The input remains open. No image decoder, renderer or resource is discovered. OpenPixels(context) supplies a read-only borrowed pixel lease under the mandatory provider context; it expires with that operation.

PdfOcr.Recognize requires an explicit IPdfOcrProvider, language token, segmentation and finite Unicode/word limits. It checks language binding, word geometry, limits and latched failures before returning a detached immutable result. Raw Unicode and words remain in engine order; block/paragraph/line/word IDs, raster-pixel boxes and optional confidence are separate observations. Confidence is not correctness. The character ceiling counts UTF16 units across both raw text and word records. No PDF coordinates or semantic reading order are inferred.

The optional non-packable Fluent.Pdf.Ocr assembly depends on core and Fluent.Pdf.Workers, independently of Word and its dependencies. IsolatedTesseractOcr uses the original fluent-pdf-ocr-1 IPC bridge version1.0, plus a separately explicit actual Tesseract5 version. The bridge checks the actual TessVersion value against the requested version before initialization; results retain that checked engine version.

The caller supplies a complete immutable NativeWorkerOptions deployment, pinning host executable, bridge, engine/dependencies and eng.traineddata by exact size/hash and native/data role. The source profile explicitly selects English and rejects other languages rather than substituting a model. Separate multilingual/model requirements remain mandatory; core language tokens do not declare model qualification.

The primary native engine uses a canonical inventory name: tesseract.dll on Windows, libtesseract.so on Linux, or libtesseract.dylib on macOS. Provision exact reviewed bytes under that name together with complete dependencies. Inside the already isolated worker, the bridge derives its own explicitly loaded module directory and loads that absolute engine path. It never searches PATH or substitutes a system engine. Model initialization receives that same explicit asset directory; the bootstrap current directory is deliberately different. No environment/default tessdata directory, model download or network service is selected.

A fresh private worker contains every job. The existing host verifies/copies/hashes assets, restricts filesystem/network/process/memory/CPU access, binds ABI/version/nonce/response lengths and supervises cancellation/deadlines. Missing sandbox facilities fail closed. C API, progress monitor, gray conversion and returned UTF8/TSV buffers have explicit bounded lifetimes; all owned handles/buffers release before the completed response. The loaded module remains until process exit, avoiding unsafe unload while native TLS/threads may survive API deletion. Threaded distributions require the explicit worker thread policy and platform prerequisites. No unqualified in-process fallback is provided.

The bridge binds every required C API export, checks native version and initializes only the explicit model. Missing symbols report the public export name. Missing/wrong-architecture/hash-mismatched assets retain precise deployment diagnostics and filenames; model initialization, allocation, recognition, Unicode, geometry and deadline failures have stable OCR codes. Process memory is reserved under the same root budget before execution. Finite text/TSV scans and one bounded response allocation prevent output-growth retries. Headerless C API TSV is normalized into an explicit canonical wire header, then parsed with bounded rows, identities, confidence, boxes and total character checks.

Capture/recognition, raster transport, isolated execution and source-result validation use mandatory operation contexts. Internal helpers allow later rendering/searchable-overlay workflows to keep one context. Caller resources stay caller-owned; staging/state is private. OCR produces data rather than persisted output; existing PDF and later interchange writers retain private serialization/atomic saves.

Reviewed MIT patterns are pinned to WN01 revision141236a3fe890d220b807a270cec2d86a8f7e3b5, distinct from the published Word dependency revision. Complete attribution/notice and source digests are in [the reuse inventory](../third-party/ocr/reuse.json). Original SDK contracts, C IPC and TSV code do not import the upstream document model, Skia/rendering dependencies, global module cache or historical runtime workarounds. See [the assessment](ocr-reuse.md).

Core and optional OCR target net472, netstandard2.0, net8.0 and net10.0. Source checks cover eleven SDK assemblies and thirty-three API comparisons. C# and VB RecognizeOcr consumers execute against explicit providers. Original C API fixtures check protocol, model/version binding, cleanup, malformed results and cancellation; they are not recognition-accuracy fixtures.

An independent tool invokes the actual bridge against Tesseract5.5.0 and an explicitly captured English model on one pre-labeled original printed raster. Expected text and source-pixel word boxes are fixed before recognition. Exact text, four boxes within one pixel and explicit CLI agreement are finite observations; the CLI uses the same engine. This does not qualify a language corpus, SDK isolation, a RID or final packages. The local host cannot execute the isolated SDK path because Landlock is unavailable; no boundary is bypassed. CI executes native contract fixtures unfiltered. Complete actual-engine integration and required qualification remain mandatory.
