# Attachments, portfolios and associated files

FP-023 has an original managed source implementation on all four core target frameworks. `PdfAttachments.Inspect` passively inventories all active file specifications and EmbeddedFile streams, including external definitions, platform variants and orphans. It retains the raw Collection dictionary and custom file-specification values. It does not execute an attachment, open an initial collection document or fetch an external file. Captured records survive disposal of their source document.

`Add` consumes a borrowed stream from its current position under shared input/expansion/object/time limits. The name must be a portable leaf of at most 240 UTF-8 bytes; Unicode UF and a compatibility F name are emitted. A duplicate EmbeddedFiles name rejects before reading the payload. The uncompressed Size and standard 16-byte MD5 CheckSum are recorded. This legacy checksum detects mismatches; it is not a cryptographic authenticity guarantee. Source dates are explicit whole-second values. No local file clock is consulted.

Ordinary Unicode attachments use PDF 1.7. An explicit AF relationship adds the same indirect file specification to the catalog AF array and EmbeddedFiles name tree and uses PDF 2.0. MIME subtype and an explicit modification timestamp are required for this authored profile. Standard/custom relationship names are retained; EncryptedPayload authoring requires the separate wrapper/encryption profile and rejects here. Source PDF/A-3-style attachments can be inspected/extracted; embedding data does not create or validate PDF/A conformance. Complete PDF/A conversion/qualification belongs to FP-066.

`Extract` selects UF, then F, or a sole remaining variant unless the caller chooses a key explicitly. It decodes into a bounded private buffer and checks declared Size, CheckSum and dates before writing any payload to the borrowed output. External files are never fetched. A corrupt payload leaves the supplied output unchanged; a later output I/O/limit failure follows the common potentially partial stream contract. Unknown decoding filters fail explicitly.

`ExtractToDirectory` requires an existing caller-controlled directory. Source names never create directories. Paths, drive/alternate-stream syntax, device names, malformed Unicode, control characters and unsafe trailing dots/spaces reject. The caller may supply a safe replacement leaf name. A private same-directory file is flushed and atomically moved with no overwrite by default; a racing existing destination also fails. Overwrite requires an explicit flag and uses atomic replacement. This does not protect a directory tree that another principal can replace during extraction; callers own the selected directory and its permissions.

`SetCollection` accepts a direct immutable standard collection dictionary: initial document, D/T/H view, schema and sort. Standard text/date/number and file-derived field types are validated, as are sort references and existing collection items. Unknown source collection data remains inspectable, while unsupported authored keys reject. `SetCollectionItem` writes an indirect CI dictionary with typed values or prefixed subitems against an explicit schema. It cannot override derived filename/size/date fields. Source references are not implicitly imported into authored direct data. This source profile supplies PDF structures; collection UI playback is outside the managed core.

`RemoveAll` stages a full rewrite, removes embedded variants/related streams, file attachment annotations, AF edges, EmbeddedFiles and Collection entries, prunes orphan objects and drops old revisions. It also clears nonstandard aliases to identified payload streams, so merely orphaning a stream cannot retain its bytes. Malformed EF/RF shapes reject when safe classification cannot be established. External references used by unrelated passive actions remain outside embedded-file removal. This operation does not redact payload copies drawn into page content.

Shared cancellation, resource accounting, immutable snapshots, signature invalidation permission and atomic save rules apply. C#/VB `WriteAttachmentPdf` examples use public contracts. Full portfolio/PDF/A/interoperability corpora, actual minimum runtimes, final package consumers and every production gate remain mandatory. NuGet packing and publication stay blocked.
