# Detached signatures and certification

FP-032 has a managed source implementation profile and an optional offline cryptography provider. Complete signature/PAdES/trust/revocation, certification-aware edit classes, native key/PKCS12/store/RID/runtime corpora and production qualification remain mandatory. NuGet packing and publishing remain blocked.

PdfSignatures.PrepareFields creates a finite batch of flat signature fields on an unsigned document. Pre-create every future signing field before the first signature. Each field belongs to an explicit page. Invisible fields have an empty rectangle; a visible field requires an explicitly supplied detached Form XObject and native unrotated PDF bounds. No handwritten mark, font, identity, time or appearance is inferred. Tagged-field creation and hierarchical imported-field signing are explicit unsupported profiles. Existing requests for implicit form-appearance regeneration reject before preparation or signing; the SDK never silently clears a form-wide appearance request.

Sign and SignFile consume an exact immutable PdfSyntaxDocument. Signing appends a classical-index revision, preserving the complete original byte prefix, earlier signatures, field identities and pre-created appearances. The target must be one unique blank indirect signature field. A finite Contents reservation and four fixed-width ByteRange integers are serialized privately. Only the exact complete hex Contents token is excluded. The signer receives the concatenated covered ranges under the same mandatory PdfOperationContext; no temporary unsigned file is published. A single bounded DER CMS is required, oversized results fail without retry, and the configured provider must verify the exact covered bytes before a result is returned. No wall-clock time is synthesized; an optional caller PDF date is not a trusted timestamp.

ManagedCmsSignatureProvider implements original offline SHA256/RSA-PKCS1 detached DER CMS with one embedded public certificate and no signed attributes. It uses pinned System.Formats.Asn110.0.13 and BouncyCastle.Cryptography2.7.0 with retained MIT notices and a locked dependency inventory. No runtime native download is introduced. A borrowed PdfCertificateCredential uses only the caller-selected RSA handle and public certificate snapshot. This includes keys selected by the caller from a platform certificate store or hardware provider. The SDK never scans a store, chooses another key, exports a private key, initiates network trust retrieval or selects a certificate implicitly. Serialize access when the caller's key provider requires it; key/PIN/UI/provider behavior requires separate qualification.

FromPkcs12 accepts an explicit bounded DER PKCS12 stream and verifies its required password MAC before importing a key. An original bounded DER parser uses the pinned managed KDF, HMAC and cipher primitives; it checks each encrypted section and shrouded key before decryption. The profile supports PBES2/PBKDF2/AES-CBC and provided-file legacy PKCS12 PBE compatibility; it never emits weak credential encryption. Limits include1MiB input,1024 password characters,16 safe sections,128 bags,64 public certificates,100000 iterations per encoded KDF and1000000 conservative aggregate hash-block iterations. More expensive or unsupported credentials require a separately budgeted caller import and an explicit borrowed handle.

Exactly one two-prime RSA2048–8192 key and one matching public certificate are required. Ambiguous private keys or matching identities reject. Decoded RSA parameters are imported into an owned memory-only RSA handle and cleared; only public certificate DER reaches the native certificate loader. Private PKCS12 data never reaches the native X509 PFX loader or a key store. This works around Apple's rejection of ephemeral native PFX loading without falling back to persisted keys. The returned provider owns its certificate/key and must be disposed; borrowed credentials remain caller-owned. Wrong passwords, MAC tampering, excessive work and unsupported profiles have stable diagnostics. Complete hostile PKCS12/KDF/platform key-provider qualification remains mandatory.

Certification must be the first signature and emits a DocMDP reference plus catalog Perms association. P=1 rejects later signing. P=2/P=3 permit only the validated profile of signing an existing unlocked blank field; they do not authorize arbitrary graph changes. FieldMDP All/Include/Exclude selections use ordinal field names and descendants. Historical transforms remain authoritative if an untrusted later revision removes their active objects. The general writer rejects protected changes unless the caller explicitly authorizes signature invalidation. A no-op incremental save preserves exact bytes. Broader permitted form-filling/annotation edit classification remains mandatory; unsupported edit classes reject conservatively.

Inspect checks active indirect signatures, ordered nonnegative two-pair ranges, the exact direct Contents gap, zero CMS padding and complete covered revision boundaries. Earlier covered prefixes must parse as complete PDFs resolving that exact signature. The provider reports cryptographic integrity. `CryptographicallyValid` is nullable: unsupported SubFilter/range profiles and CMS signed attributes produce an observation with no verdict and a stable `UnsupportedReason`, while supported signatures continue to be inspected. Legal whitespace/comments between the Contents key and hex token are accepted. Signing times must be explicit whole seconds and are validated when options are constructed. TrustEvaluated is false: expiry, identity, chain trust, revocation, trusted time, PAdES conformance and whether arbitrary external later edits were permitted require separate validation. An intact CMS can coexist with a forbidden later edit; do not interpret CryptographicallyValid as document authorization.

PdfSignedResult retains immutable exact signed bytes. Saving requires an empty seekable borrowed sink, keeping old prefixes/tails from silently changing the complete file. Caller streams remain open. Stream copy failure can leave a partial result. SignFile and SaveFile stage privately and atomically replace the destination after all checks succeed. Cancellation, latched limits and provider failures prevent file replacement.

The original independent fixture uses pre-created fields, an explicit red Form appearance, a caller-provisioned in-memory PKCS12 and an original self-signed test certificate. OpenSSL3.5.7 and Poppler25.03 validate all three observed signatures across the certification and twice-signed outputs. PyHanko0.31 accepts the second unlocked signature under DocMDP/FieldMDP, and independently rejects a later page rotation while the CMS bytes remain intact. Covered-byte mutation fails independent CMS verification. Trust is evaluated only against the explicit original test root, with digitalSignature usage, network disabled and unavailable revocation recorded; no public/system trust or revocation qualification is inferred. Signed visual pixels match prior rectangle/color/page-size labels. The initial checker used the viewer's generated unsigned-widget placeholder as its visual baseline; the original failure, exact adapter diff and hashes are retained. No output, label, permission or threshold changed.
