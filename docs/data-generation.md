# Document events and typed data generation

FP-099 has an original source profile. Complete event/model/data/provider coverage and production qualification remain mandatory; NuGet packing/publication remain blocked.

`PdfDataGeneration.Generate`, `Write` and `WriteFile` accept a typed source, an immutable `PdfGenerationTemplate<T>`, explicit providers and `PdfGenerationOptions`. Options require explicit layout and a standard culture name; empty explicitly selects invariant culture. The culture is captured read-only without user overrides. Templates explicitly select every field, style, font and captured resource; the SDK never reflects over records, invokes arbitrary object ToString, discovers fonts or resolves external names/URLs implicitly.

```csharp
var template = new PdfGenerationTemplate<Order>("order", (context, order) =>
{
    context.Paragraph(context.Format(order.Total, "N2"), explicitTextStyle);
});
var options = new PdfGenerationOptions(layout, "de-DE",
    pageTemplate: explicitPageTemplate, maximumRecords: 1000,
    observer: phase => Observe(phase.Kind, phase.RecordsPrepared, phase.PageCount));
PdfDataGeneration.WriteFile(orders, template, options, explicitProviders, selectedPath);
```

All SDK-owned enumeration, scalar/table binding, template invocation, flow/convergent page layout, model assembly, shaping and serialization share one mandatory operation context. Internal binding/layout/model/write helpers preserve public APIs while eliminating nested budget resets. Template document creation now accounts for body plus decorations under one context; model population attaches that context to page/resource mutations. A returned Generate document is caller-owned; a later public Save is explicitly a separate operation. Write/WriteFile keep generation and serialization in the same operation and dispose their private model afterward. Default generation writing requests PDF 1.7 and therefore needs a writer honoring nondefault version choices; explicit caller write options are validated by the selected writer. No archival or accessibility conformance follows.

The synchronous hook order is Starting; for each root record, RecordStarting, TemplateStarting, TemplatePrepared, RecordPrepared; then LayoutStarting, LayoutPrepared, PagePrepared for each final physical page; for writing, SaveStarting and SavePrepared; finally Prepared. Nested templates add properly nested TemplateStarting/TemplatePrepared phases. TemplatePrepared means blocks were captured, and SavePrepared means bytes were serialized privately. Every user hook runs before successful return or atomic file publication. Prepared is followed by final resource checks and publication, so it does not announce that a destination is already committed.

Hook views expose ordinal, root record/count, block count, template identity/depth, final page count and immutable page observations (geometry, occupied extent and line/table/column/note counts). They expose no live editable document, output stream, unfinished layout report or canvas. Hook exceptions propagate; cancellation/deadline/latched policy failures retain precedence. Hooks can inspect metadata and perform cooperative context work. Captured-builder Add/Apply/AddTable during observation rejects with a latched `Generation.ReentrantMutation`, including when the callback catches the exception. Building outside a template, cross-thread use and expired context reuse have separate diagnostics. New generation state is private to each operation; caller-owned delegate/provider state must obey the same concurrency contract as other extensions.

Templates use Add/Paragraph for immutable blocks, AddTable for bounded typed binding, Format for closed scalar conversion and Apply for nested typed templates. Finite reference-record trees and value-record recursion are supported within depth/resource limits. An active repeated template/reference-record identity pair rejects as `Generation.TemplateCycle` without invoking user equality/hash methods; value records use the depth ceiling. Source self-cycles reject. Enumeration uses at most the explicit record ceiling plus one lookahead, disposes its enumerator and checkpoints before/after callback/enumerator work. Captured blocks and dispatched observer calls have separate explicit ceilings; ordinary object/input/expansion/output/depth/worker/time budgets still apply. Scalar formatting shares the closed, bounded table formatter and stable Table.* diagnostics. Null handling and field selection remain explicit template choices.

Callbacks, enumerators and supplied providers are synchronous and cooperative. They must account for their own allocations with the supplied context and finish all workers/scopes before returning. Arbitrary blocking/async/fire-and-forget extension code is not a qualified isolation boundary. A stale builder rejects further mutation; no private model can escape before success. Complete asynchronous/uncooperative host isolation and document-wide editing/event integration remain mandatory profiles.

Write leaves borrowed streams open at their current position; failure can leave a prefix. WriteFile serializes privately, runs every hook and checks all scopes/workers before atomic replacement. Late hook failure, cancellation, output limits or a leaked worker preserve an existing destination. No user callback runs after atomic publication. Page decorations and contents/numbering use the explicit existing page-template contract and its full qualification gaps.

Source contracts execute both C#/VB consumers, exact hook traces/shared provider contexts, actual pagination, stale/thread/reentrant safeguards, original exceptions, record lookahead/disposal, finite/cyclic templates, explicit culture/closed scalar formatting, typed tables/decorations, 1000-record enumeration, resource limits, cancellation and atomic leaked-worker failures. Independent original outputs cover five cases/seven pages with pypdf, MuPDF and Poppler. Source-stream and geometric reader order are tested against their respective declared views. These observations are not production qualification.
