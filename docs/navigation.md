# Navigation and action policy

FP-020 has an original managed source implementation on the four core target frameworks. It emits standard local destinations, name trees, Link annotations, URI/GoTo/GoToR/Launch actions, catalog OpenAction/additional actions and page open/close actions. No operation executes imported actions, runs scripts, starts applications, reads referenced files or fetches URIs. A PDF viewer may perform an emitted action later; callers choose the policy for their output.

`PdfDestination` uses zero-based physical input pages and native unrotated coordinates. XYZ permits null retained coordinates and zero retained zoom; Fit/FitB, width/height variants and positive FitR rectangles have exact arity checks. Applying it captures an indirect page identity. Page moves retain that identity. Source saves validate reachable local targets, named destinations and view arrays before writing. A destination to a removed page fails with `Navigation.RemovedTarget`; callers must explicitly retarget/remove it or use page organization with its omitted-destination policy. Page imports resolve names and remap page references through the existing organization boundary. Duplicate-page and excluded-target policies remain explicit.

`PdfNavigation.SetNamedDestination` creates/replaces/removes one Unicode name, consolidates legacy byte-valued destination keys into a byte-sorted name tree, preserves unrelated name trees and rejects byte/decoded-name ambiguity. Deleting a name still used by a local action fails validation. Name-tree cycles/order errors and destination cycles/malformed views have stable diagnostics. Large name trees are bounded by the common operation limits; no process-wide cache is used.

`PdfAction` is immutable. Local GoTo, named GoTo, absolute URI, remote named destination and file launch have factories. `Then` captures a finite ordered action batch. `Advanced` accepts an original detached dictionary without Next; references are rejected under the operation budget and nested streams are promoted to indirect objects. Typed actions and advanced definitions share policy and destination checks. Advanced subtype semantics require caller knowledge and independent validation; this does not implement script execution, submission, forms, embedded-document traversal or media playback.

The default `PdfActionPolicy` permits local GoTo and absolute HTTP/HTTPS URI actions. Remote-file navigation, launch, JavaScript and other actions require explicit opt-in. URI schemes are an immutable caller list; relative, control-bearing and non-ASCII source URIs are blocked. `allowUri: false` and `allowLocalGoTo: false` permit a no-actions policy. Retention permissions do not grant network/process/script execution. A caller authoring actions must retain the returned document; each operation stages a separate result and leaves its input snapshot intact.

`PdfNavigation.Inspect` enumerates all active indirect objects, including orphan definitions, plus direct dictionaries/arrays and physical action attachment locations. Shared action references have separate attachment records; their object definitions appear independently. It covers catalog OpenAction and AA; page AA; annotation/widget/screen A/AA; outline A; JavaScript name-tree definitions; Next dictionaries/arrays; action dictionaries in other object locations; and opaque XFA, RichMedia and 3D activation/script-bearing entries. Unknown subtypes at known action slots remain inspectable and blocked by default. General resource/structure dictionaries with an unrelated S key are not treated as actions. Locations identify object numbers and direct paths, not an exponentially expanded path for each route through a shared object graph. Next cycles fail; repeated acyclic shared nodes are valid.

`Sanitize` explicitly removes policy-blocked actions and opaque active-content keys across the active object overlay, prunes blocked chain entries, removes the document JavaScript name tree when scripts are blocked and reports `Navigation.ActionsRemoved`. A blocked parent action removes its attached sequence. Malformed/cyclic action graphs fail explicitly. The operation does not inspect historical revisions, foreign document formats inside attachments, XML script languages or arbitrary extension semantics. It is an action-retention policy, not a general malware classifier or secure erasure. Payload bytes may remain in unreferenced source objects or history; redaction/recovery guarantees belong to their separate mandatory requirement. Signature invalidation still requires explicit organization options.

All parsing/editing uses the shared context, finite object/expanded-byte/depth/time limits and cancellation. Caller streams remain owned by callers; path saves remain atomic. C#/VB `WriteNavigationPdf` emits linked named destinations and an initial GoTo action. Source tests exercise nested/shared/cyclic chains, indirect AA, widgets/outlines/scripts/orphans, removed targets, all view modes, Unicode names, policy denial, cancellation and detached ownership. Full navigation/action corpus, independent viewers, fuzzing, actual minimum Framework runtimes, exact final packages and all production gates remain mandatory. Source validation never enables NuGet packing or publishing.
