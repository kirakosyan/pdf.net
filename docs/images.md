# Images and reusable page graphics

FP-017 has a managed source implementation, with the same public API on all four target frameworks. It is not production-qualified. The core adds no image, color-management or native runtime dependency and does not render PDFs. Optional PDF image codecs remain explicit providers described in [stream filters](pdf-filters.md).

`PdfImages.FromSamples`, `FromStencil`, `FromRgba` and `FromEncoded` capture caller-owned streams into immutable detached assets. Packed 1/2/4/8/16-bit samples, one through 32 declared color components, Decode arrays, interpolation, stencils, matching grayscale soft masks, explicit hard masks and encoded-domain color keys retain their precision. Raw RGBA separates unassociated color and alpha planes exactly. Mask attachments change dictionaries without changing encoded image bytes. Native image providers reject geometries outside their codec profiles before starting a worker.

`Read` accepts PNG and single-image 8-bit Gray/RGB/CMYK baseline, extended-sequential or progressive JPEG. JPEG packets remain byte-identical, with bounded marker/scan framing, ICC segment assembly, Adobe color-transform/inversion declarations, JFIF/Exif density and all eight orientation values. Header framing does not validate compressed entropy; decoding requires an explicit DCT provider. Other file containers, JPEG processes and animation require explicit adapters.

PNG parsing checks chunk bounds, names, CRCs, ordering, singleton declarations, critical chunks and terminal extent. Opaque noninterlaced images keep the original concatenated IDAT bytes and PNG predictor parameters. Alpha separation and Adam7 reconstruction require `AllowLosslessTranscode`; they preserve every sample and precision, while recording the representation change. Indexed images retain their palette and original packed indices; partial palette opacity produces a separate exact mask. Physical resolution/aspect, Exif orientation, ICC, sRGB intent and gamma/chromaticity declarations are explicit. HDR declarations require a caller-supplied matching color-space override. Incompatible color declarations fail. Original PNG/JPEG container bytes remain separately exportable.

`PdfImageAsset.WriteEncoded` exports exact PDF filter bytes. `WriteOriginalFile` exports the original image container where retained. Both preserve caller stream ownership and enforce output budgets. `OpenSamples` returns an owned bounded stream before Decode/color/alpha interpretation; it performs no color conversion and discovers no codec implicitly. Display aspect accounts for nonsquare pixels and orientation. `NaturalSize` is available only when physical DPI is known. `PdfCanvas.DrawImageAsset` applies orientation in an explicit unit-square Form and offers the existing contain/cover/stretch placement choices. Owned XMP display metadata survives PDF extraction; parsing prohibits DTDs and external entities and bounds XML extent/depth.

`PdfPageGraphics.Inspect` captures an immutable source snapshot and walks actual Do/inline invocations in depth-first paint order. Repeated uses remain separate. Each occurrence exposes original encoded definition, operator index and accumulated matrix into native page user coordinates, including enclosing Form matrices. Surrounding clipping/operators remain in the captured programs; the matrix is not a rendered visible outline. Scoped named inline color spaces resolve without searching for an ambiguous EI sequence. Inspection runs no document action or optional image decoder. Raw signed graphs can be inspected without rewriting them.

`ExtractImage` detaches typed image definitions, profiles and masks without recompression. Geometry declared only inside a codec requires an explicit adapter; the raw occurrence definition remains available for byte-preserving inspection. `ExtractResource` also detaches reusable Forms with their effective resource scopes. Cyclic resource graphs, optional-content ownership and structure parent associations require an owner-preserving import profile and fail explicitly rather than flattening those relationships. Extraction does not reconstruct an original PNG/JPEG container when only PDF filter bytes exist.

`Remove`, `ReplaceImage` and `ReplaceResource` create a separate staged document and clone the selected enclosing Form path, leaving other invocations of shared Forms unchanged. Image replacement retains the original unit-square frame/clip/transform and applies replacement orientation; changing aspect is an explicit content/layout decision. Resource replacement retains the replacement Form's declared bounds and matrix. Removing an invocation is ordinary content editing: old objects/resources may remain in the resulting graph, so this is not secure redaction. Structured source content edits require an explicit association-preservation profile; signed full rewrites require `AllowSignatureInvalidation`. Saving to paths uses the existing atomic writer.

`Deduplicate` operates only within an explicit finite batch. It hashes metadata, original-file identity, complete dictionaries, masks/profiles and stream bytes, then compares the full graphs and bytes after hashing. Different Decode/color/mask/display semantics cannot alias. Owner-dependent resources, metadata streams and unknown image keys are conservatively excluded. There is no process-global image cache.

Pixel geometry is charged before sample allocations or decoder work. Input, expansion, object, depth, pixel, output and cancellation budgets share one operation context across nested parsing, form traversal, extraction and editing. Work on repeated invocations is charged independently. Caller streams and source documents remain caller-owned.

## Original profile and fixture provenance

`eng/generate-image-profiles.py` creates original ICC v2.1 RGB/grayscale matrix/shaper data from normative standard RGB facts (neutral facts STD-COLOR-RGB and STD-COLOR-ICC). It uses D65 primaries, original Bradford adaptation to exact ICC D50, normalized black and a 4096-entry unsigned-16-bit inverse transfer curve. No third-party profile bytes or implementation bodies are copied. These finite sampled profiles do not implement a color-management engine or qualify arbitrary color transforms. The data directory retains deterministic hashes and original MIT provenance. PNG/TIFF orientation facts use neutral IDs STD-IMAGE-PNG3 and STD-IMAGE-TIFF6; raw primary-source captures belong outside the repository.

`eng/generate-image-fixtures.py` creates owned synthetic color, monochrome, CMYK, alpha, palette, precision, profile and orientation fixtures. Tests retain exact original files, packet/predictor bytes and known samples. C# and VB examples emit real image PDFs using caller streams. Full independent corpus/conformance/color/visual qualification, actual minimum Framework runtimes, final package consumers, fuzzing and complete resource/concurrency/endurance gates remain mandatory. NuGet candidate creation and publication remain blocked.
