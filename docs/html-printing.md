# HTML print layout and structural tagging

FP-047 has an original source profile. The full requirement remains planned and mandatory; these observations do not qualify a browser host, PDF/UA, a production runtime or a final package. NuGet packing and publication remain blocked.

`PdfHtmlOptions.WithPrint` returns an immutable options snapshot containing `PdfHtmlPrintOptions`, preserving the existing public constructors. Explicit choices include fallback paper, landscape, scale 0.1–2, four margins in PDF points, CSS page-size precedence and headers/footers. The adapter converts points to browser inches, explicitly disables default tagging, and retains actual generated page boxes. CSS page breaks, @page and repeated table headers are evaluated by the exact caller-pinned browser. A source fixture permits one point of physical paper quantization; it never changes imported boxes to manufacture an exact nominal size.

```csharp
var options = new PdfHtmlOptions(pageSize: new PdfPageSize(300, 400))
    .WithPrint(new PdfHtmlPrintOptions(
        marginTop: 36, marginBottom: 36, marginLeft: 24, marginRight: 24,
        headerHtml: "<div style=\"font-size:10px\"><span class=\"pageNumber\"></span>/<span class=\"totalPages\"></span></div>",
        tagged: true));
using var document = PdfHtml.Render(source, explicitlyConfiguredProviders, options);
```

The C#/VB contract consumers exercise the public snapshot API. Templates require a corresponding positive top/bottom margin and a positive fallback content rectangle. Fragments are bounded to 65536 UTF-16 units and validated under the same operation context before opening a host. The current resource-free XHTML profile allows common text/table/list elements and class/title/inline literal CSS. Scripts, event attributes, images/SVG, external resources, style elements, DTDs/entities, malformed XML and CSS functions/imports are rejected as `Html.PrintTemplateProfile`, with source content omitted from diagnostics. Canonical output escapes text and attributes. Native `pageNumber` and `totalPages` refer to final printed pages. The deployment host must provide explicit qualified template fonts; the development counter fixture uses an explicit generic monospace family with unqualified host font selection.

When `Tagged` is requested, ordinary managed PDF import is followed by bounded passive structural association checks before returning a document. The shared context covers MarkInfo/StructTreeRoot, indirect structure-element identity and parent links, page MCIDs, number-tree order/limits/cycles, ParentTreeNextKey and bidirectional parent-array associations. Missing, duplicate, cyclic or inconsistent associations fail with `Html.TagStructure`. Page MCIDs and marked-content references are supported; Form-stream and object-reference associations fail explicitly with `Html.TagStructureProfile`. Generic semantic role mapping, attributes, IDs, full namespace validation and PDF/UA authoring/validation remain mandatory work under FP-067/FP-101; no accessibility conformance claim follows from structural association checks. Ordinary source-content edits continue to require an explicit structure-preservation policy.

The original browser observer produces three explicitly separated pages with matching header/footer counters; a 90-row, six-page table with repeated headers; CSS paper precedence and fallback fitting; landscape paper; full/half-scale SVG vectors; and two structurally tagged outputs. Independent pypdf, MuPDF and Poppler spatial-layout observations check all 14 pages, counters, clipping bounds, exact source/spatial text, vector dimensions and structure relationships. Poppler default column grouping places centered table headers after body text, while its spatial-layout mode preserves visual order; default reading-order interoperability remains unqualified. Managed extraction explicitly rejects a browser-emitted Type 3 font matrix (`Extraction.Type3MatrixProfile`). These findings remain in evidence rather than being normalized into a qualification pass.
