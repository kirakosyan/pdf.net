# FP-036: AcroForm creation and editing

Status: **Planned**. Area: interaction. SDK production release requirement: **yes**.

The managed [AcroForm source profile](../forms.md) is under validation. Its field/widget and appearance APIs do not establish complete interactive viewer, structure or production qualification; the remaining profiles and release gates are mandatory.

## Scope

Create and edit text, checkbox, radio, choice, push-button and signature fields, widgets, names, flags, appearances and calculations metadata.

## Dependencies

- [FP-008](FP-008.md)
- [FP-011](FP-011.md)
- [FP-019](FP-019.md)

## Acceptance criteria

- [ ] Field trees and duplicate names remain valid.
- [ ] Unicode field values have usable appearances.
- [ ] Tab order and tagged field relationships are preserved.
- [ ] Exercise strict/unsupported-content diagnostics, resource boundaries and cancellation wherever applicable.
- [ ] Keep public API, capability documentation, platform applicability and package-only examples synchronized.
- [ ] Record actual evidence from every applicable production lane; compilation alone does not qualify behavior.

## Validation

Form subtype corpus; independent viewer fill/edit round trips and collision tests.

The common [production qualification gates](../production-quality.md) also apply. An independent reader/validator must be used where this requirement emits a standard format.

## Non-goals

- Features owned by other requirements except integration through public contracts.
- Silent fallback, unqualified support claims or changes to the approved production release scope.

## Evidence lineage

A01, B01, D01, D02. See the [research report](../research.md) for source classes, observation limits and the distinction between declared API and verified runtime behavior.
