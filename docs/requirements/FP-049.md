# FP-049: Isolated rendering service and container deployment

Status: **Planned**. Area: web. SDK production release requirement: **yes**.

## Scope

Offer local process and optional self-hosted worker transport for browser/native jobs on containers, serverless and restricted hosts without requiring a hosted vendor service.

## Dependencies

- [FP-044](FP-044.md)
- [FP-045](FP-045.md)
- [FP-046](FP-046.md)
- [FP-085](FP-085.md)

## Acceptance criteria

- [ ] Authenticate worker transport and apply per-tenant quotas.
- [ ] Retry only idempotent operations with explicit bounds.
- [ ] No unsolicited binary/model downloads occur at runtime.
- [ ] Exercise strict/unsupported-content diagnostics, resource boundaries and cancellation wherever applicable.
- [ ] Keep public API, capability documentation, platform applicability and package-only examples synchronized.
- [ ] Record actual evidence from every applicable production lane; compilation alone does not qualify behavior.

## Validation

Docker rootless and read-only filesystem tests; worker restarts, transport failures and tenant isolation.

The common [production qualification gates](../production-quality.md) also apply. An independent reader/validator must be used where this requirement emits a standard format.

## Non-goals

- Features owned by other requirements except integration through public contracts.
- Silent fallback, unqualified support claims or changes to the approved production release scope.

## Evidence lineage

B01, D02, ENH. See the [research report](../research.md) for source classes, observation limits and the distinction between declared API and verified runtime behavior.

## Source progress

An original [authenticated static-render worker protocol](../render-service.md) now provides explicit client/service/tenant boundaries and hosted/container source examples. Complete general browser/native transport, actual host/security/container integration and production qualification remain mandatory; status remains Planned.
