# FP-044: HTML, CSS and JavaScript to PDF

Status: **Planned**. Area: web. SDK production release requirement: **yes**.

## Scope

Provide an optional Chromium-based HTML/file/URL renderer supporting HTML5, CSS layout, JavaScript, SVG, canvas, web fonts and local resources.

## Dependencies

- [FP-002](FP-002.md)
- [FP-008](FP-008.md)
- [FP-040](FP-040.md)

## Acceptance criteria

- [ ] Browser engine versions are pinned and inspectable.
- [ ] Execution uses an isolated per-job browser context.
- [ ] Browser output imports into the same editable PDF model.
- [ ] Exercise strict/unsupported-content diagnostics, resource boundaries and cancellation wherever applicable.
- [ ] Keep public API, capability documentation, platform applicability and package-only examples synchronized.
- [ ] Record actual evidence from every applicable production lane; compilation alone does not qualify behavior.

## Validation

Browser fixture corpus with grid/flex, SVG/canvas, fonts and dynamic layouts on every supported RID.

The common [production qualification gates](../production-quality.md) also apply. An independent reader/validator must be used where this requirement emits a standard format.

## Non-goals

- Features owned by other requirements except integration through public contracts.
- Silent fallback, unqualified support claims or changes to the approved production release scope.

## Evidence lineage

B01, D02. See the [research report](../research.md) for source classes, observation limits and the distinction between declared API and verified runtime behavior.
