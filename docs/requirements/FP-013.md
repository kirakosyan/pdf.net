# FP-013: Tables and data binding

Status: **Planned**. Area: composition. SDK production release requirement: **yes**.

## Scope

Create nested tables with merged cells, borders, padding, styles, fixed/auto widths, repeated headers, row splitting and bounded data-source binding.

## Dependencies

- [FP-012](FP-012.md)

## Acceptance criteria

- [ ] Keep merged cells and repeat headers correct across pages.
- [ ] Bind typed records and null values using explicit culture.
- [ ] Reject cyclic or unbounded data sources within budgets.
- [ ] Exercise strict/unsupported-content diagnostics, resource boundaries and cancellation wherever applicable.
- [ ] Keep public API, capability documentation, platform applicability and package-only examples synchronized.
- [ ] Record actual evidence from every applicable production lane; compilation alone does not qualify behavior.

## Validation

Invoice and nested-table goldens; large-table streaming and row-split edge cases.

The common [production qualification gates](../production-quality.md) also apply. An independent reader/validator must be used where this requirement emits a standard format.

## Non-goals

- Features owned by other requirements except integration through public contracts.
- Silent fallback, unqualified support claims or changes to the approved production release scope.

## Evidence lineage

A01, D01, WN01. See the [research report](../research.md) for source classes, observation limits and the distinction between declared API and verified runtime behavior.

## Implementation progress

Original managed source now supplies immutable merged/nested grids, cell styling/padding/borders, fixed/automatic widths, repeated and stacked nested headers, safe row fragments and bounded typed/culture-aware scalar binding. Source and independent development tests do not replace complete business/table goldens, minimum runtimes, final packages or required production fidelity/security/long-workload qualification.
