# FP-080: Semantic chunking and retrieval adapters

Status: **Planned**. Area: intelligence. SDK production release requirement: **yes**.

## Scope

Expose layout-aware semantic chunks, table boundaries, token budgets, embeddings and vector-store adapters while preserving page and permission provenance.

## Dependencies

- [FP-025](FP-025.md)
- [FP-027](FP-027.md)
- [FP-067](FP-067.md)
- [FP-079](FP-079.md)

## Acceptance criteria

- [ ] Chunk boundaries do not lose source text.
- [ ] Embedding model/dimension/version are recorded.
- [ ] Cache and tenancy controls prevent cross-document leakage.
- [ ] Exercise strict/unsupported-content diagnostics, resource boundaries and cancellation wherever applicable.
- [ ] Keep public API, capability documentation, platform applicability and package-only examples synchronized.
- [ ] Record actual evidence from every applicable production lane; compilation alone does not qualify behavior.

## Validation

Labeled chunk corpus, retrieval relevance measurements, cancellation and tenant-isolation tests.

The common [production qualification gates](../production-quality.md) also apply. An independent reader/validator must be used where this requirement emits a standard format.

## Non-goals

- Features owned by other requirements except integration through public contracts.
- Silent fallback, unqualified support claims or changes to the approved production release scope.

## Evidence lineage

A01, D01, ENH. See the [research report](../research.md) for source classes, observation limits and the distinction between declared API and verified runtime behavior.

An explicit [chunking and scoped retrieval profile](../semantic-retrieval.md) is available for source validation. Complete tagged semantic profiles, real model/tokenizer/store/transport/relevance/security/runtime/final-package qualification and all acceptance checkboxes remain mandatory and open.
