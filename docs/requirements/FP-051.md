# FP-051: Raster documents to PDF

Status: **Planned**. Area: conversion. SDK production release requirement: **yes**.

## Scope

Convert JPEG, PNG, BMP, GIF, TIFF/multipage TIFF, WebP, HEIF/HEIC and other explicitly enumerated image formats through optional codecs with EXIF/DPI/page controls.

## Dependencies

- [FP-011](FP-011.md)
- [FP-017](FP-017.md)

## Acceptance criteria

- [ ] Multi-frame selection and animation handling are explicit.
- [ ] Preserve color and alpha according to output policy.
- [ ] Unsupported codec availability is reported before conversion.
- [ ] Exercise strict/unsupported-content diagnostics, resource boundaries and cancellation wherever applicable.
- [ ] Keep public API, capability documentation, platform applicability and package-only examples synchronized.
- [ ] Record actual evidence from every applicable production lane; compilation alone does not qualify behavior.

## Validation

Per-codec multi-frame, orientation, DPI and color fixtures; licensing and RID checks.

The common [production qualification gates](../production-quality.md) also apply. An independent reader/validator must be used where this requirement emits a standard format.

## Non-goals

- Features owned by other requirements except integration through public contracts.
- Silent fallback, unqualified support claims or changes to the approved production release scope.

## Evidence lineage

A01, B01, D01, D02, ENH. See the [research report](../research.md) for source classes, observation limits and the distinction between declared API and verified runtime behavior.

## Source progress

An original [raster-document composition profile](../raster-import.md) handles managed PNG/JPEG and explicitly supplied bounded frame decoders. Real extra-codec profiles, complete animation/color/precision and production qualification remain mandatory; status remains Planned.
