# FP-073: Linearization and progressive access

Status: **Planned**. Area: production. SDK production release requirement: **yes**.

## Scope

Write and validate web-optimized linearized PDFs, range-readable sources, lazy page/resource access and bounded caches.

## Dependencies

- [FP-003](FP-003.md)
- [FP-005](FP-005.md)
- [FP-016](FP-016.md)
- [FP-072](FP-072.md)

## Acceptance criteria

- [ ] Hint tables and offsets are independently valid.
- [ ] Range providers honor cancellation and authentication policy.
- [ ] Document edits invalidate or rebuild linearization correctly.
- [ ] Exercise strict/unsupported-content diagnostics, resource boundaries and cancellation wherever applicable.
- [ ] Keep public API, capability documentation, platform applicability and package-only examples synchronized.
- [ ] Record actual evidence from every applicable production lane; compilation alone does not qualify behavior.

## Validation

Independent linearization checks, simulated HTTP range server and first-page latency tests.

The common [production qualification gates](../production-quality.md) also apply. An independent reader/validator must be used where this requirement emits a standard format.

## Non-goals

- Features owned by other requirements except integration through public contracts.
- Silent fallback, unqualified support claims or changes to the approved production release scope.

## Implementation progress

An original bounded range session now supports selective page dictionaries, lazy indirect resource/stream access, per-revision private LRU caches, authorization checks on warm reads, detached results and shared cancellation/resource budgets. Explicit staged linearization producer/independent-validator gates bind exact candidate and request bytes; ordinary edits remove stale linearization. See [progressive access](../progressive-access.md). Complete independent hint validation, qualified producer/transport/corpus/performance/host/final-package coverage remain mandatory; status remains Planned.
