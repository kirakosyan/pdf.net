# FP-086: Runtime and architecture qualification

Status: **Planned**. Area: production. SDK production release requirement: **yes**.

## Scope

Source CI includes a hardware-backed Windows Server 2019 guest runner for actual Framework 4.7.2 x86/x64. The [runtime procedure](../runtime-qualification.md) distinguishes same-binary source observations, synthetic controls, host qualification and final-package consumers. The source runner does not complete this requirement by itself.

Qualify exact packages on Windows/Linux/macOS x64/ARM64 modern .NET and Windows x86/x64 actual .NET Framework 4.7.2 plus current Framework, including netstandard fallback consumers.

## Dependencies

- [FP-001](FP-001.md)
- [FP-085](FP-085.md)

## Acceptance criteria

- [ ] A target framework declaration is never runtime evidence.
- [ ] Every applicable lane reports zero failures and zero skips.
- [ ] Platform-specific features have explicit applicability rather than hidden skips.
- [ ] Exercise strict/unsupported-content diagnostics, resource boundaries and cancellation wherever applicable.
- [ ] Keep public API, capability documentation, platform applicability and package-only examples synchronized.
- [ ] Record actual evidence from every applicable production lane; compilation alone does not qualify behavior.

## Validation

Native host and isolated minimum-runtime reports with OS, runtime, RID, package hashes and complete test totals.

The common [production qualification gates](../production-quality.md) also apply. An independent reader/validator must be used where this requirement emits a standard format.

## Non-goals

- Features owned by other requirements except integration through public contracts.
- Silent fallback, unqualified support claims or changes to the approved production release scope.

## Evidence lineage

WN01, ENH. See the [research report](../research.md) for source classes, observation limits and the distinction between declared API and verified runtime behavior.
