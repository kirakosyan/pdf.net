# FP-018: Watermarks, stamps and artifacts

Status: **Planned**. Area: composition. SDK production release requirement: **yes**.

Source progress: [owned stamp capture/inspection/update/removal and decoration classification](../stamps.md) are under source validation. Full profiles and production qualification remain mandatory; visible removal is not redaction.

## Scope

Apply, inspect, update and remove text, image, HTML and PDF-page stamps with opacity, rotation, repetition, placement and artifact classification.

## Dependencies

- [FP-011](FP-011.md)
- [FP-015](FP-015.md)
- [FP-017](FP-017.md)

## Acceptance criteria

- [ ] Target exact page ranges and foreground/background layers.
- [ ] Removal identifies owned stamps without deleting unrelated content.
- [ ] Tagged output distinguishes content from decoration.
- [ ] Exercise strict/unsupported-content diagnostics, resource boundaries and cancellation wherever applicable.
- [ ] Keep public API, capability documentation, platform applicability and package-only examples synchronized.
- [ ] Record actual evidence from every applicable production lane; compilation alone does not qualify behavior.

## Validation

Repeated stamping/removal cycles; clipping and transparency visual fixtures.

The common [production qualification gates](../production-quality.md) also apply. An independent reader/validator must be used where this requirement emits a standard format.

## Non-goals

- Features owned by other requirements except integration through public contracts.
- Silent fallback, unqualified support claims or changes to the approved production release scope.

## Evidence lineage

A01, B01, D01, D02. See the [research report](../research.md) for source classes, observation limits and the distinction between declared API and verified runtime behavior.
