# FP-056: PDF to HTML and semantic web output

Status: **Planned**. Area: conversion. SDK production release requirement: **yes**.

## Scope

Export fixed-layout or reflow HTML with CSS, images, fonts, links, headings and tables; support self-contained output and controlled asset callbacks.

## Dependencies

- [FP-019](FP-019.md)
- [FP-020](FP-020.md)
- [FP-025](FP-025.md)
- [FP-028](FP-028.md)
- [FP-040](FP-040.md)

## Acceptance criteria

- [ ] Preserve reading order and navigation semantics.
- [ ] Sanitize generated markup and untrusted actions.
- [ ] Record all rasterized or unreconstructed content.
- [ ] Exercise strict/unsupported-content diagnostics, resource boundaries and cancellation wherever applicable.
- [ ] Keep public API, capability documentation, platform applicability and package-only examples synchronized.
- [ ] Record actual evidence from every applicable production lane; compilation alone does not qualify behavior.

## Validation

Browser rendering versus source raster; accessibility checks, CSP/offline asset and text comparisons.

The common [production qualification gates](../production-quality.md) also apply. An independent reader/validator must be used where this requirement emits a standard format.

## Non-goals

- Features owned by other requirements except integration through public contracts.
- Silent fallback, unqualified support claims or changes to the approved production release scope.

## Evidence lineage

A01, D01. See the [research report](../research.md) for source classes, observation limits and the distinction between declared API and verified runtime behavior.

## Source implementation progress

Offline HTML5 export now provides explicitly rendered self-contained pages or declared-loss inferred text, with static CSP, escaped markup and page provenance. See [html-export](../html-export.md) for the exact supported profile. The full scope and all production gates remain mandatory; status remains Planned.
