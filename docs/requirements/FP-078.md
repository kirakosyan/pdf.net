# FP-078: Barcode and QR document workflows

Status: **Planned**. Area: ocr. SDK production release requirement: **yes**.

## Scope

Provide optional barcode/QR generation and detection integrated with PDF placement and page/region extraction, including structured invoice/payment payload validation.

## Dependencies

- [FP-017](FP-017.md)
- [FP-040](FP-040.md)
- [FP-074](FP-074.md)

## Acceptance criteria

- [ ] State supported symbologies and error correction explicitly.
- [ ] Return page coordinates and payload encoding safely.
- [ ] No generated symbol is accepted without independent decoding.
- [ ] Exercise strict/unsupported-content diagnostics, resource boundaries and cancellation wherever applicable.
- [ ] Keep public API, capability documentation, platform applicability and package-only examples synchronized.
- [ ] Record actual evidence from every applicable production lane; compilation alone does not qualify behavior.

## Validation

Independent barcode decoder tests, rotated/damaged symbols and multilingual payload fixtures.

The common [production qualification gates](../production-quality.md) also apply. An independent reader/validator must be used where this requirement emits a standard format.

## Non-goals

- Features owned by other requirements except integration through public contracts.
- Silent fallback, unqualified support claims or changes to the approved production release scope.

## Implementation progress

Original QR Model2 versions1–40 and Code128B generation now require independent exact decoding before returning a vector symbol, with explicit optional managed decoding, page/region landmark mapping and canonical EPC002/UTF8 EUR invoice/payment validation. See [barcode workflows](../barcodes.md) and [dependency notices](../../third-party/barcodes/README.md). Full profiles, corpus/scanner/payment/security/concurrency/host and exact final-package qualification remain mandatory; status remains Planned.
