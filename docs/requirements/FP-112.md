# FP-112: Document templates and mail merge

Status: **Planned**. Area: composition. SDK production release requirement: **yes**.

## Scope

Fill DOCX and native PDF generation templates with scalar fields, repeating records, conditions, images and explicit culture, then export through shared providers.

## Dependencies

- [FP-013](FP-013.md)
- [FP-050](FP-050.md)
- [FP-053](FP-053.md)
- [FP-099](FP-099.md)

## Acceptance criteria

- [ ] Use the optional wordnet adapter for document-format semantics.
- [ ] Bound template evaluation and never execute arbitrary code.
- [ ] Keep field errors and missing-data policy explicit.
- [ ] Exercise strict/unsupported-content diagnostics, resource boundaries and cancellation wherever applicable.
- [ ] Keep public API, capability documentation, platform applicability and package-only examples synchronized.
- [ ] Record actual evidence from every applicable production lane; compilation alone does not qualify behavior.

## Validation

Invoice/mail-merge consumers, empty/missing/large collections, escaping and multilingual formatting fixtures.

The common [production qualification gates](../production-quality.md) also apply. An independent reader/validator must be used where this requirement emits a standard format.

## Non-goals

- Features owned by other requirements except integration through public contracts.
- Silent fallback, unqualified support claims or changes to the approved production release scope.

## Evidence lineage

B01, WN01, ENH. See the [research report](../research.md) for source classes, observation limits and the distinction between declared API and verified runtime behavior.
