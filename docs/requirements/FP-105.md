# FP-105: Cross-platform native distribution packages

Status: **Planned**. Area: production. SDK production release requirement: **yes**.

## Scope

Build and qualify optional RID-specific rendering, browser and OCR asset packages or offline provisioning manifests for Windows, Linux and macOS.

## Acceptance criteria

- [ ] Every shipped binary has version/hash/license and supported ABI metadata.
- [ ] No GDI+/desktop-only assumption leaks into Linux/macOS core.
- [ ] Air-gapped installs succeed from documented artifacts.
- [ ] Exercise strict/unsupported-content diagnostics, resource boundaries and cancellation wherever applicable.
- [ ] Keep public API, capability documentation, platform applicability and package-only examples synchronized.
- [ ] Record actual evidence from every applicable production lane; compilation alone does not qualify behavior.

## Validation

Clean offline container/host installations on every supported RID and dependency-probe reports.

The common [production qualification gates](../production-quality.md) also apply. An independent reader/validator must be used where this requirement emits a standard format.

## Non-goals

- Features owned by other requirements except integration through public contracts.
- Silent fallback, unqualified support claims or changes to the approved production release scope.

## Source implementation progress

Original source-fixture observations do not qualify native engine distributions, system ABI or clean air-gapped hosts. Status remains Planned; #93 remains user-skipped and mandatory.

The subsequent [installed-renderer source observer](../native-distribution.md) provisions the actual pinned engine and complete declared notices offline, executes public SDK worker/full-page/region paths, rejects missing/changed assets and retains real pixels/runtime identities. It extends finite source evidence; complete reviewed distributions and clean-host/system-ABI/other-engine/runtime/package qualification remain mandatory.
