# FP-085: Native provider deployment and isolation

Status: **Planned**. Area: production. SDK production release requirement: **yes**.

## Scope

Define RID-specific packaging/provisioning, exact engine versions, hashes, dependency probes, sandbox boundaries, safe library search and crash recovery.

## Dependencies

- [FP-001](FP-001.md)
- [FP-002](FP-002.md)

## Acceptance criteria

- [ ] No runtime binary download or PATH-based unsafe loading by default.
- [ ] Providers report architecture, ABI and missing dependency details.
- [ ] Native crash/resource limits cannot corrupt the caller's persisted output.
- [ ] Exercise strict/unsupported-content diagnostics, resource boundaries and cancellation wherever applicable.
- [ ] Keep public API, capability documentation, platform applicability and package-only examples synchronized.
- [ ] Record actual evidence from every applicable production lane; compilation alone does not qualify behavior.

## Validation

Windows/Linux/macOS x64/ARM64 deployment probes, wrong ABI, read-only filesystem and crash injection.

The common [production qualification gates](../production-quality.md) also apply. An independent reader/validator must be used where this requirement emits a standard format.

## Non-goals

- Features owned by other requirements except integration through public contracts.
- Silent fallback, unqualified support claims or changes to the approved production release scope.

## Evidence lineage

WN01, B01, ENH. See the [research report](../research.md) for source classes, observation limits and the distinction between declared API and verified runtime behavior.
