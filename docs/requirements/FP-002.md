# FP-002: Operation policies, diagnostics and resource budgets

Status: **Planned**. Area: foundation. SDK production release requirement: **yes**.

## Scope

Implement strict and permissive policies with stable diagnostic codes, bounded input/output, decompression, object counts, recursion, pixels, elapsed time and cancellation.

## Dependencies

- [FP-001](FP-001.md)

## Acceptance criteria

- [ ] Strict mode rejects unsupported requested behavior before returning success.
- [ ] Permissive results include every loss with page/object context.
- [ ] All budget failures release handles and leave atomic outputs unpublished.
- [ ] Exercise strict/unsupported-content diagnostics, resource boundaries and cancellation wherever applicable.
- [ ] Keep public API, capability documentation, platform applicability and package-only examples synchronized.
- [ ] Record actual evidence from every applicable production lane; compilation alone does not qualify behavior.

## Validation

Boundary and overflow tests for each limit; cancellation at parse, render and save stages.

The common [production qualification gates](../production-quality.md) also apply. An independent reader/validator must be used where this requirement emits a standard format.

## Non-goals

- Features owned by other requirements except integration through public contracts.
- Silent fallback, unqualified support claims or changes to the approved production release scope.

## Evidence lineage

ENH, A01, B01. See the [research report](../research.md) for source classes, observation limits and the distinction between declared API and verified runtime behavior.
