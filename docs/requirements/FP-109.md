# FP-109: Task-oriented facades and plugin composition

Status: **Planned**. Area: integration. SDK production release requirement: **yes**.

## Scope

Expose concise task APIs for generation, conversion, extraction, form filling and optimization with streams, file collections and dependency-injected optional plugins.

- [FP-001](FP-001.md)
- [FP-016](FP-016.md)

- [FP-065](FP-065.md)
- [FP-071](FP-071.md)

## Acceptance criteria

- [ ] Facades use the same policies and diagnostics as the document model.
- [ ] No duplicate PDF engine or license dependency is introduced.
- [ ] Document every facade's resource ownership and provider requirements.
- [ ] Exercise strict/unsupported-content diagnostics, resource boundaries and cancellation wherever applicable.
- [ ] Keep public API, capability documentation, platform applicability and package-only examples synchronized.
- [ ] Record actual evidence from every applicable production lane; compilation alone does not qualify behavior.

## Validation

Facade-to-core equivalence tests, minimal C#/VB/F# samples and missing-provider diagnostics.

The common [production qualification gates](../production-quality.md) also apply. An independent reader/validator must be used where this requirement emits a standard format.

## Non-goals

- Features owned by other requirements except integration through public contracts.
- Silent fallback, unqualified support claims or changes to the approved production release scope.

## Evidence lineage

A01, D01, B01, ENH. See the [research report](../research.md) for source classes, observation limits and the distinction between declared API and verified runtime behavior.
