# FP-107: DjVu and CDR document import

Status: **Planned**. Area: conversion. SDK production release requirement: **yes**.

## Scope

Import DjVu scanned documents and CDR vector documents using optional isolated format adapters with explicit supported versions, compression, page and font behavior.

## Dependencies

- [FP-002](FP-002.md)
- [FP-040](FP-040.md)
- [FP-085](FP-085.md)

## Acceptance criteria

- [ ] Publish exact supported format versions and read-only limitations.
- [ ] Keep interpreter file/network access bounded.
- [ ] Report unsupported records and missing codecs instead of producing empty pages.
- [ ] Exercise strict/unsupported-content diagnostics, resource boundaries and cancellation wherever applicable.
- [ ] Keep public API, capability documentation, platform applicability and package-only examples synchronized.
- [ ] Record actual evidence from every applicable production lane; compilation alone does not qualify behavior.

## Validation

Independent readers and versioned DjVu/CDR fixtures; damaged streams, font failures and sandbox tests.

The common [production qualification gates](../production-quality.md) also apply. An independent reader/validator must be used where this requirement emits a standard format.

## Non-goals

- Features owned by other requirements except integration through public contracts.
- Silent fallback, unqualified support claims or changes to the approved production release scope.

## Evidence lineage

A01, ENH. See the [research report](../research.md) for source classes, observation limits and the distinction between declared API and verified runtime behavior.
