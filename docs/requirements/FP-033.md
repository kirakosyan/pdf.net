# FP-033: Signature verification and trust decisions

Status: **Planned**. Area: security. SDK production release requirement: **yes**.

## Scope

Verify cryptographic integrity, signer chains, signed revisions, certification permissions, timestamp trust and tampering with explicit trust-store and offline/revocation policy.

## Dependencies

- [FP-003](FP-003.md)
- [FP-032](FP-032.md)

## Acceptance criteria

- [ ] Report mathematical validity separately from identity trust.
- [ ] Unknown/offline revocation never becomes an unconditional valid result.
- [ ] Identify which revisions are signed and later modifications.
- [ ] Exercise strict/unsupported-content diagnostics, resource boundaries and cancellation wherever applicable.
- [ ] Keep public API, capability documentation, platform applicability and package-only examples synchronized.
- [ ] Record actual evidence from every applicable production lane; compilation alone does not qualify behavior.

## Validation

Trusted/untrusted/expired/revoked chains, tampered byte ranges and offline fixtures.

The common [production qualification gates](../production-quality.md) also apply. An independent reader/validator must be used where this requirement emits a standard format.

## Non-goals

- Features owned by other requirements except integration through public contracts.
- Silent fallback, unqualified support claims or changes to the approved production release scope.

## Evidence lineage

A01, B01, D01. See the [research report](../research.md) for source classes, observation limits and the distinction between declared API and verified runtime behavior.
