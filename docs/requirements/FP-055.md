# FP-055: Presentation conversion

Status: **Planned**. Area: conversion. SDK production release requirement: **yes**.

## Scope

Convert PDF to editable or image-based PPTX and supported presentation input to PDF with explicit object reconstruction and slide/page geometry.

## Dependencies

- [FP-010](FP-010.md)
- [FP-017](FP-017.md)
- [FP-025](FP-025.md)
- [FP-040](FP-040.md)

## Acceptance criteria

- [ ] Preserve slide size and page ordering.
- [ ] Distinguish editable objects from raster fallback.
- [ ] Disclose missing fonts and unsupported effects.
- [ ] Exercise strict/unsupported-content diagnostics, resource boundaries and cancellation wherever applicable.
- [ ] Keep public API, capability documentation, platform applicability and package-only examples synchronized.
- [ ] Record actual evidence from every applicable production lane; compilation alone does not qualify behavior.

## Validation

Independent presentation readers; mixed text/vector/image decks and visual output comparison.

The common [production qualification gates](../production-quality.md) also apply. An independent reader/validator must be used where this requirement emits a standard format.

## Non-goals

- Features owned by other requirements except integration through public contracts.
- Silent fallback, unqualified support claims or changes to the approved production release scope.

## Evidence lineage

A01, D01, ENH. See the [research report](../research.md) for source classes, observation limits and the distinction between declared API and verified runtime behavior.

## Source implementation progress

Explicit image-based PPTX export and strict picture-only import now preserve selection order, common EMU slide geometry and lossless embedded raster assets. See [presentations](../presentations.md) for the exact supported profile. The full scope and all production gates remain mandatory; status remains Planned.
