# FP-081: Windows COM interoperability

Status: **Planned**. Area: integration. SDK production release requirement: **yes**.

## Scope

Provide a separate COM-visible facade for supported Windows automation clients with stable GUIDs, explicit marshaling, registration guidance and bitness support.

## Dependencies

- [FP-001](FP-001.md)
- [FP-016](FP-016.md)
- [FP-025](FP-025.md)
- [FP-031](FP-031.md)
- [FP-036](FP-036.md)

## Acceptance criteria

- [ ] Keep COM types out of cross-platform core.
- [ ] Translate diagnostics and ownership rules predictably.
- [ ] Test both x86 and x64 clients on actual Framework runtimes.
- [ ] Exercise strict/unsupported-content diagnostics, resource boundaries and cancellation wherever applicable.
- [ ] Keep public API, capability documentation, platform applicability and package-only examples synchronized.
- [ ] Record actual evidence from every applicable production lane; compilation alone does not qualify behavior.

## Validation

VBScript and native COM consumer samples; registration/unregistration and error marshaling tests.

The common [production qualification gates](../production-quality.md) also apply. An independent reader/validator must be used where this requirement emits a standard format.

## Non-goals

- Features owned by other requirements except integration through public contracts.
- Silent fallback, unqualified support claims or changes to the approved production release scope.

## Evidence lineage

D01, ENH. See the [research report](../research.md) for source classes, observation limits and the distinction between declared API and verified runtime behavior.
