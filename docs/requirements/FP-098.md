# FP-098: PDF 2.0 and extension preservation

Status: **Planned**. Area: foundation. SDK production release requirement: **yes**.

## Scope

Handle PDF 2.0 dictionaries, Unicode strings, associated files, namespaces, encryption and version-specific changes; preserve unsupported extension payloads safely.

## Dependencies

- [FP-003](FP-003.md)
- [FP-005](FP-005.md)
- [FP-007](FP-007.md)
- [FP-016](FP-016.md)

## Acceptance criteria

- [ ] Publish a version/extension read-write-preserve matrix.
- [ ] Editing cannot silently discard unknown safe extension data.
- [ ] Strict output negotiation rejects incompatible requested features.
- [ ] Exercise strict/unsupported-content diagnostics, resource boundaries and cancellation wherever applicable.
- [ ] Keep public API, capability documentation, platform applicability and package-only examples synchronized.
- [ ] Record actual evidence from every applicable production lane; compilation alone does not qualify behavior.

## Validation

PDF 1.x/2.0 interop corpus and exact opaque-payload preservation tests.

The common [production qualification gates](../production-quality.md) also apply. An independent reader/validator must be used where this requirement emits a standard format.

## Non-goals

- Features owned by other requirements except integration through public contracts.
- Silent fallback, unqualified support claims or changes to the approved production release scope.

## Evidence lineage

A01, D01, ENH. See the [research report](../research.md) for source classes, observation limits and the distinction between declared API and verified runtime behavior.
