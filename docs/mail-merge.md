# Document templates and mail merge

FP-112 has a source-validation profile. Complete DOCX/native template semantics, multilingual and layout fidelity, hostile-input/corpus/runtime/package qualification and all production gates remain mandatory. NuGet candidate creation and publication remain blocked.

`PdfMailMerge.Generate`, `Write` and `WriteFile` evaluate an immutable `PdfMergeTemplate` with explicitly captured `PdfMergeRecord` data. Blocks provide styled paragraphs, finite repetitions, boolean conditions, captured PNG images and tables with explicit columns/headers. Runs contain literal text or closed dotted field paths. Native output uses existing shared generation, layout, fonts, page events and writer providers.

`PdfMergeValue` accepts only closed scalar formatting types, immutable records/finite captured collections and explicit images. It does not reflect arbitrary objects. Paths select captured records; `root.` selects the original record and `@index` selects the zero-based repeat index. Conditions require actual boolean values. There are no scripts, property getters, dynamic expressions, implicit files, URLs or font discovery. Data inserted into templates is text and is never evaluated again.

`PdfMergeEvaluationOptions` captures a standard culture by explicit name, with empty selecting invariant. Native options take the same culture from `PdfGenerationOptions`. Number/date formatting uses the bounded shared formatter rather than ambient culture. Missing fields have an explicit error, empty or preserved-scalar policy, with stable information diagnostics for caller-selected omissions. Preserved structural/image fields reject; present null scalars format as empty. Type/path/instruction errors remain typed failures.

The optional `Fluent.Pdf.Word` assembly provides `PdfDocxMailMerge.Write`, `WriteFile` and `GeneratePdf`. DOCX scalars use `{{path}}` or `{{path:format}}`, including markers split across text runs. Replacement retains the first covered run's style and unrelated text. Standard content-control tags select `merge:field:path[:format]`, `merge:each:path`, `merge:if:path` or `merge:image:path`. False conditions and empty repeats remove the selected content. Scalar data is escaped XML, forbidden XML characters reject, and unknown merge instructions never execute. There is no expression language or source field execution.

Filled DOCX preserves unrelated package parts. Source packages pass the Word adapter's passive bounded preflight before XML loading. DTDs, resolvers, active parts, external resources and traversal remain denied. Owned PNG parts/relationships use fresh checked identities and explicit point geometry. Repetition of existing bookmarks, comment ranges or drawings rejects until identity rebinding is implemented; owned image controls support repeated images. Full Word stories, complex field/identity/control semantics and complete reconstruction remain mandatory pending profiles.

`GeneratePdf` invokes the explicitly registered `IPdfWordConverter` through the actual pinned wordnet adapter under the same root context. It inherits that adapter's explicit font adoption, source limits, strict/permissive losses and remaining fidelity obligations. Unrelated parts that upstream conversion omits remain warning losses in permissive mode and strict-mode failures. Direct filled-DOCX preservation does not imply identical PDF conversion semantics.

All parsing, binding, repeated visits, data formatting, private package/model assembly, provider calls and output share one operation context. Default evaluation limits are 100,000 visits and expanded records, independently bounded to at most one million; root object/depth/input/expansion/output/time limits still apply. Images are captured explicitly before use and revalidated/charged in the merge operation. Caller streams remain open. Private serialization completes before caller-stream copy or atomic destination replacement. Caller-stream write failures can leave a prefix; failed evaluation never commits an existing file destination.

Core and optional Word contracts target net472, netstandard2.0, net8.0 and net10.0. Actual provider/OS/runtime behavior and exact final-package consumers require independent qualification on all required lanes. C# and VB `MergePdf` source consumers execute through public contracts. Source tests include invoices, explicit German formatting, split fields, escaping, literal marker data, finite/empty collections, independent jobs, images, missing/type/path policies, cancellation, budgets and atomic output. Independent Open XML schema, Word/XML/image and unrelated PDF readers inspect original output; these observations do not establish complete fidelity or production readiness.
