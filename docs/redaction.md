# Raster redaction and full-rewrite sanitization

FP-030 has an explicit source implementation profile. Complete selective editable-content preservation, rendering/security corpora and production qualification remain mandatory. NuGet packing and publishing remain blocked.

PdfRedaction.RasterRewrite requires an explicit page renderer, DPI and displayed top-left CropBox physical-point rectangles. Selected pixels are replaced before RGB encoding. All pages are rasterized into a fresh graph; source text/vector programs, fonts, tags, forms, metadata, attachments, actions, optional-content objects, unreachable objects and original revision bytes are discarded. SanitizeRasterRewrite performs the same fresh raster rewrite without removal rectangles. No document action is executed by the managed transformation.

This is a deliberately destructive flattening profile. Unmasked visible content survives only as pixels at the caller's resolution. Digital text, accessibility structure, editable vectors and fields are lost. Visible annotation/widget appearances require explicit opt-in; they never remain interactive. The caller must qualify and trust its configured renderer, including its visible-layer and matte behavior. The SDK validates exact raster dimensions, opaque samples, limits and source geometry; these checks do not establish rendering correctness.

Every removal rectangle must fit the displayed crop. Boundaries round outward to raster pixels, add explicit padding and clip to the page. Overlaps count once. Mask work, regions, pixels, allocations, stream IO and cancellation use one mandatory PdfOperationContext through preparation, rendering, masking, encoding, fresh serialization and structural verification. All output pages normalize their displayed crop to rotation0/UserUnit1. The fresh writer never adopts any original object or byte prefix.

Existing signature byte ranges reject before rendering unless invalidation is explicitly authorized. Rewriting discards signatures and cannot preserve their validity. The audit contains counts, requested/actual geometry, signature presence and the new output SHA-256 only. It contains no removed text, names, URIs or payload hashes. OperationReport is separate: third-party provider diagnostics can contain caller/provider data and are not a sanitized removal audit.

WriteRasterRewrite privately constructs and checks the complete output before copying it. Borrowed sinks must be empty and seekable at position0, preventing old prefixes/tails from retaining sensitive data. The caller retains stream ownership. Stream-copy failure may leave a sanitized prefix. File methods stage privately and replace atomically only after success. These APIs do not erase filesystem backups, original inputs, temporary provider assets or external storage histories.

The original independent corpus includes overlapping text/image/vector content, hidden layers, metadata, an attachment, actions, an unreachable payload, rotation/CropBox/UserUnit and an incremental prior revision. Independent object/decoded-stream/raw-byte/text recovery found none of the declared removed payloads in three outputs. New decoded images and independent rendered pixels match the expected replacement masks exactly, including unchanged pixels outside masks. Two upright outputs retain their visible public text under explicit tool OCR; rotated OCR returned no text. Captured MuPDF rasters are bound to exact original source hashes by a fixture provider; this does not qualify the SDK native renderer/host or a complete security corpus.

ISO32000-1:2008 §12.5.6.23 distinguishes identification annotations from actual removal, requires destruction of image samples within removed regions and consideration of hidden metadata/content. The implementation uses replacement samples and a fresh object graph rather than clipping or cover annotations.
