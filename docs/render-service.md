# Authenticated render-worker protocol

FP-049 / queue #63 adds an original authenticated static-HTML worker protocol, explicit client/service boundaries, a hosted HTTPS transport example and a non-root container recipe. Complete isolated host/container/serverless, native/browser engine and production qualification remain mandatory. The tracking requirement remains Planned.

`PdfRenderWorkerClient` and `PdfRenderWorkerService` use a finite version-one binary frame. HMAC-SHA256 authenticates direction, exact ASCII tenant, fresh 128-bit request nonce, source SHA256, payload length and payload. The service verifies authentication before invoking its configured renderer. The client verifies authentication, nonce/source binding and nonempty structural PDF import before exposing immutable PDF bytes. A replayed response cannot satisfy a new nonce. The service retains each accepted nonce for its lifetime in a per-tenant set bounded by `MaximumJobs`; duplicates reject as `Worker.Replay` before concurrency acquisition or job charging, including while the original job is running. Caller-owned `PdfWorkerCredentials` capture 32–64-byte keys and clear their copies on disposal; keys and raw exception messages are never logged by these APIs. HMAC supplies authenticity, not confidentiality: provision protected local channels or authenticated TLS.

At most64 explicit tenants may be registered. Per-tenant active jobs, lifetime accepted jobs, source bytes, generated-PDF bytes and tightened deadlines are finite. Nonce acceptance and job/concurrency acquisition are atomic per tenant, and active leases release on failure/cancellation. Each service request has its own mandatory operation context; the client keeps its own cumulative transport/output budget. Input is capped at 8 MiB UTF8 HTML and output at 64 MiB PDF, further tightened by tenant/global policies. Frames authenticate and transmit segmented immutable payloads with bounded incremental hashing and small headers; PDF payload slices share their capture storage. A 60 MiB PDF regression retains the default 256 MiB expanded-byte budget. No ambient account, endpoint, engine, model, browser or native asset is discovered/downloaded.

Only the documented idempotent static-HTML profile is implemented. It uses default A4/1280x720/en-US/UTC/print/background options, disabled JavaScript, the reserved virtual origin and no resource map. Non-default options or addressed/resource-backed sources reject with `Worker.OptionsUnsupported` before transport. The service must use an explicitly provisioned isolated offline renderer; provider/resource/OS isolation remains the host's responsibility. General browser/native RPC option profiles and remote raster transport remain required future work.

Retries default to one attempt. A caller may select at most three; only `PdfWorkerTransientException` retries the same exact authenticated request. Generic transport/render errors are redacted, policy/cancellation failures propagate, and partial results never become client PDF success. Each accepted service attempt consumes the tenant's job allowance. A transient failure before server acceptance can retry; if the server already accepted that nonce, its replay rejection prevents a second render. Lost responses require host reconciliation; this protocol does not cache completed PDFs. It cannot authorize a mutating print/signing operation.

The [web sample](../examples/Fluent.Pdf.WebSample/Program.cs) exposes bounded asynchronous HTTP ingress and a worker endpoint only when the application explicitly registers tenants/credentials and a real service renderer. Missing prerequisites return 503. Its [HTTPS transport example](../examples/Fluent.Pdf.WebSample/WorkerHttpTransport.cs) disables redirects, cookies, proxies and decompression, applies context cancellation and preserves bounded response streams. Applications needing a proxy or private trust policy must supply their own explicitly configured transport. The sample never installs a fake renderer on regular endpoints.

[The Dockerfile](../examples/Fluent.Pdf.WebSample/Dockerfile) requires a caller-selected pinned runtime-image digest and published app directory; it runs as UID/GID65532 with diagnostics disabled. Provision renderer assets and writable private engine scratch explicitly. Use a read-only root, explicit temporary mounts, dropped capabilities, no-new-privileges and a controlled network policy; a required host sandbox must continue to work inside that boundary. No image was published or container/real engine qualified by these source checks. Exact rootless/read-only/restart/tenant/transport/serverless evidence remains mandatory.

Contract tests cover authenticated round trips, expired leases/keys, request/response tampering, tenant separation, replay binding, exact bounded retries, concurrency/job/input quotas, cancellation/resources and invalid/backend-failed outputs. These protocol fixtures do not qualify a browser, TLS stack, container or production service.
