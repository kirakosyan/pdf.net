# Archival conversion and validation source profile

FP-066 now has explicit PDF/A-1a/1b, 2a/2b/2u, 3a/3b/3u and 4/4e/4f profile contracts, managed structural preflight, a bounded full-rewrite conversion path and an optional independent-validation report bridge. These are source profiles; full production qualification remains pending and packing/publication stay blocked.

`PdfArchival.Inspect` inventories common blockers without declaring conformance. It checks encryption, font embedding, dynamic forms, external streams, prohibited actions, level-A structure, profile-specific attachment restrictions and PDF/A-1 optional content/transparency/blend/JPEG 2000 constraints. Zero findings means only that these structural checks found no blocker. It does not establish PDF/A compliance or semantic accessibility.

`PdfArchival.Convert` requires an explicit complete `IPdfArchivalValidator`. It stages a full rewrite, writes synchronized standard XMP/profile identification and required file IDs, optionally installs a caller-supplied complete RGB/CMYK ICC output intent, then validates the exact staged bytes and requested profile. Only a complete compliant observation with a matching SHA-256 can authorize copying to caller output. There is no metadata-only success path or default validator. The generic writer retains its version-downgrade refusal; a private archival staging path permits an explicit downgrade only behind the independent output gate. Typed feature-version and signature guards still apply.

Fonts must already be embedded by the document/font APIs or supplied by the source. No machine font is substituted. PDF/A-1 conversion can add a missing CIDSet from an explicit complete CID-to-GID stream map, using a private descriptor and a reported structural repair. Identity-map/CFF CID inventories and additional font conversion/embedding profiles remain mandatory work. Existing output intents can be retained; an explicit ICC v2 profile compatible with PDF 1.4 is required for PDF/A-1 output intent authoring. No implicit color conversion or transparency rasterization occurs.

Existing semantic tags are required for level A. The converter never invents tags for arbitrary content. PDF/A-4f requires an embedded-file name tree; attachment authoring supplies explicit filenames, MIME, descriptions, times and associated-file relationships. The current preflight rejects attachments for PDF/A-1/2; recursive PDF/A-2 attachment validation remains a separate required profile. Conversion never decrypts protection implicitly or executes document actions. Use explicit security, action-removal, form/static appearance, layer and content-editing workflows first when required.

`replaceMetadata` explicitly requests a new XMP packet synchronized from standard Info fields. It reports `Archival.MetadataReplaced` as an omission; strict mode rejects that loss, and permissive mode retains its diagnostic. It is an archival metadata repair, not a forensic sanitization guarantee. Unsupported repairs fail. Existing signatures require explicit invalidation permission and a reported rewrite. Validation failures attach their bounded detached `PdfArchivalValidation` to `PdfException.Data["Fluent.Pdf.ArchivalValidation"]`, so a caller can inspect the rule findings while converted output remains untouched.

`PdfArchival.Validate` returns a complete/incomplete independent observation on exact caller input, with findings, source digest and SDK operation report. A noncompliant result is a validation observation rather than successful conversion. Conversion exposes its validated observation and full operation report separately. Provider capability registration is not engine or SDK production qualification.

Optional `Fluent.Pdf.Compliance.VeraPdfReportValidator` parses veraPDF 1.28.2 reports from an explicitly supplied `PdfArchivalValidationRunner`. The runner receives borrowed PDF/report streams and the mandatory context. The bridge performs no engine installation, process launch, network access or temporary-file creation. The caller configures a complete offline validation host, supervised execution/isolation and any explicit staging/retention. This integration boundary is trusted extension code; the complete SDK-owned isolated runtime adapter remains required work. The source fixture host is explicitly test-only and does not qualify OS isolation.

The bridge bounds XML to 16 MiB and 10,000 rule findings, prohibits DTDs/resolvers and verifies exact engine version, profile, XML paths, one job, complete rule/check counts, batch failures and consistency. Malformed, truncated, contradictory or mismatched results fail closed. One operation context covers graph preparation, metadata/ICC/font repair, writing, hashing, provider input/report parsing and final copying. Caller streams remain open and use their current positions. A stream I/O failure during the final copy can leave partial bytes; this profile exposes no file-path save method.

Source tests run the pinned independent engine on all 11 requested profiles using original explicitly decorative tagged/artifact fixtures. They also validate embedded TrueType Unicode under 1b/2u/3u, metadata repair, malformed reports, budgets and cancellation. These small fixtures do not qualify arbitrary conversions, a complete font/color/form/attachment/extension corpus or level-A semantic/human review. C#/VB consumers and API comparisons cover all library targets. Actual minimum runtimes, the complete isolated host, independent fidelity/reconstruction, complete repair profiles, fuzz/concurrency/endurance, engine/dependency review and exact final-package consumers remain mandatory.
