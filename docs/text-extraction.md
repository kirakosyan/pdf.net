# Text extraction with geometry

FP-025 has an original managed source profile on the four core frameworks. `PdfTextExtraction.ReadPage` reads page and nested Form content under one operation context. It preserves source execution order separately from source-declared ActualText and geometric line/paragraph inference. It never runs actions, renders glyph programs, searches machine fonts, performs OCR or downloads CMaps.

Each `PdfExtractedCharacter` represents one encoded source character code and its Unicode cluster. A ligature can map to several scalars sharing one cell. ToUnicode, ActualText, inferred simple encodings and unmapped replacements have distinct provenance; source declarations do not establish linguistic correctness. Unknown mappings fail in strict mode and produce diagnosed U+FFFD replacements in permissive mode. `ActualTextSpans` retain logical replacements over raw code ranges without fabricating a separate physical box for each logical scalar. A replacement crossing selected/excluded content rejects in strict mode; permissive mode reports the unavailable replacement and retains selected raw mappings.

Geometry follows text/line matrices, CTM, font size, horizontal scale, character/word spacing, rise, TJ adjustments, quote operators and local Form matrices/resources. q/Q preserves graphics/text state while text matrices follow their separate PDF lifetime. Native unrotated quads and displayed top-left quads/baselines remain separate. Display coordinates include CropBox origin, viewing rotation and UserUnit. Returned cells use declared advances and font height metrics; **they are advance cells, not glyph ink outlines or a promise of exact clipping/occlusion visibility**.

The source font profile covers simple fonts with declared widths, standard fonts through an explicit encoding-metrics provider, Identity-H/V CID fonts with W/DW and W2/DW2, and the supported standard Type 3 font matrix. ToUnicode is parsed once per selected font. Optional `IPdfFontEncodingProvider` handles declared simple encodings, with an inference diagnostic. The optional managed font provider also implements `IPdfFontEncodingMetricsProvider`: widths follow the encoded glyph name, independently of a potentially different ToUnicode replacement. Core extraction has no dependency on that package when the PDF supplies the required mappings/metrics. Missing height estimates are explicit strict/permissive losses, with returned geometry flagged.

Options explicitly select hidden layers and nonpainting text. Ordinary extraction retains searchable nonpainting text and respects the default optional-content view. Hidden text still advances the text matrix even when it is excluded from results, and an excluded unmapped code does not invent Unicode. LayerVisible and RenderingMode are reported separately; clipping and visual occlusion are not inferred as certain visibility. Named/alternate layer configuration and the explicit usage profile use FP-024.

`RawText` concatenates mapped clusters in execution order. `Text` applies source ActualText and positional separators. `Words` retain raw code order; `Lines`, `Paragraphs` and `LayoutText` are separate geometric inferences with finite tolerances and bounded spacing. They do not assert original linguistic order, accessibility structure or complete column reconstruction. In particular, logical multilingual text can come from ActualText while the corresponding raw glyph/word order remains observable. Additional linguistic/column/vertical reconstruction profiles and ink geometry remain mandatory qualification work.

Additional source CMaps/CID encodings, arbitrary Type 3 matrices, and text represented through pattern/glyph programs or annotation appearances need further explicit profiles. Ordinary page/Form extraction does not evaluate those programs as a source of linguistic text. All work shares cancellation, input/expansion/object/depth/time limits and immutable captured source data. Returned records survive document disposal. C#/VB `ExtractPageText` consumers use borrowed input streams; final package consumers remain blocked with packing/publication. Full multilingual/geometry/fidelity corpora, actual minimum runtimes, final packages and every production gate remain required.
