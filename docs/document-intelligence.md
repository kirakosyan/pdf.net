# Explicit document intelligence

The optional `Fluent.Pdf.Intelligence` assembly provides `PdfDocumentIntelligence.Analyze` for summarization, question answering, translation, image descriptions, configured image OCR and closed-schema structured extraction. The caller supplies a model provider and at least one explicit page/region selection. A missing provider fails; no model, endpoint, HTTP client, credentials or native assets are discovered or downloaded. The core retains its model-independent managed boundary.

Each operation captures immutable `PdfIntelligenceModel` identity, exact model version, location, fixed endpoint, context ceiling and explicitly configured prices. A remote model requires a matching `AllowedRemoteOrigin` for that operation before source capture or provider preparation. Remote endpoints require HTTPS without URI credentials/query/fragment. Local endpoints are explicit literal-loopback HTTP(S); in-process providers may omit the endpoint. Model metadata/support/preparation methods must be offline. Caller-owned transports enforce origin/address/TLS/authentication/redirect policy and shared cancellation. There is no default network implementation.

The selected source profile transfers only captured mapped character text or explicitly authorized selected-region PNGs. It does not transfer original PDF bytes, metadata, attachments, actions or unselected pages. Text excludes optional-content-hidden and nonpainting modes, rejects estimated character geometry and includes only positive advance cells fully inside the selected displayed region. Text is source-order clusters with explicit gaps, rather than a semantic reading-order assertion. Color, occlusion, transparency and misleading source mappings can conceal text without changing those flags: extraction is not redaction or proof of visible ink. Use explicitly sanitized sources or authorized rendered-region inputs when that distinction matters. Image tasks require separate `AllowImages` authority and an explicitly configured renderer. There is no automatic OCR fallback.

Parsing, extraction/rendering, PNG capture, hashing, request preparation, execution, response parsing, schema checks and provenance checks share one mandatory operation context. Source/citation/structured-text counts, input/output tokens, configured-rate cost, JSON extents/depth, input/expanded/output bytes, pixels, objects, cancellation and deadlines are finite. The default configured-cost ceiling is zero. Conservative reservations are checked before execution, and returned usage must match the exact model/request and remain within the reservation. Costs use explicit six-fractional-digit rates and currency without conversion; they are calculated configured-rate observations, not verified invoices or account-wide billing limits. Exact token bounds, backend enforcement, pricing and response metering require qualification. External charges cannot be undone after a failed response.

`PdfChatDocumentModel` is an original closed chat-completions JSON-schema adapter over `IPdfIntelligenceTransport`. It serializes one fixed system role and one user data envelope, quotes excerpts separately from trusted task controls, uses only captured `data:image/png` image content, and requests one nonstreamed/nonstored completion at temperature zero with tool choice disabled. Every declared structured member must be required in this strict chat profile. Optional-member schemas require a separately qualified provider; no silent schema fallback occurs. The adapter reserves the entire serialized UTF8 wire request using a configured byte-token upper bound and requires exact returned model identity, complete ordinary assistant JSON, coherent reported token totals and the echoed request digest. Truncation, refusal, tool/function calls, unsolicited response members and malformed/duplicate/precision-losing JSON reject. No tool, follow-up URL, function, returned markup, document action or implicit retry is executed. `store:false` requests backend behavior; it does not prove service retention practices.

Prompt isolation limits SDK authority and data flow. It does not prove that a model will linguistically ignore every hostile document instruction or produce a correct answer. Trusted provider/transport implementations require their own isolation and servicing qualification. Recordings are used only as labeled tests, never as a runtime fallback.

Every accepted result has canonical `DataJson`, exact request binding, bounded reported usage, immutable model configuration and resolved `Evidence`. The schema supports closed objects, bounded arrays, Unicode-scalar string lengths/enumerations, exact decimal numbers, signed64-bit integers, booleans, null and explicit nullable values. General external references, arbitrary code, regex validators and dynamic object binding are absent. Each substantive output value needs a validated citation path. Text quotes must occur once exactly in the selected source; source IDs/pages/frames/hashes are resolved by the SDK. Image evidence identifies an exact captured image frame with an empty quote, without claiming an unverified word box. Frames use displayed top-left physical points and quote offsets use UTF16. Region values are serialized as round-trip numeric strings to retain the exact source coordinates. Quote matching and schema success do not establish semantic, linguistic, OCR or factual correctness.

Source/image/cost/token authorities are immutable per job. Request/source/schema/model/pricing/limit bindings are SHA256; no source payload or credentials enter diagnostics. Model and transport instances remain caller-owned, must honor shared contexts and may be shared only if their implementation isolates jobs. Borrowed request/image leases must be disposed before provider return; the SDK closes owned response bodies, including cancellation immediately after transport return. No global payload cache, shared credential configuration or mutable model selection is introduced.

Compiled C# and VB examples call `AnalyzeSelectedText` with an explicit provider/options object. Source validation uses original two-page PDF fixtures and deterministic labeled adapter recordings, including every task, source filtering, role-delimiter/exfiltration attempts, missing authority, schema/citation/usage/version failures and cleanup. An independent JSON Schema implementation, PDF text reader and PNG reader check captured sources and accepted outputs. Those tests do not execute or qualify a live local/remote model, translation quality, OCR accuracy, service data retention, real transport/isolation/SSRF policies, model pricing/tokenizers, all runtime/RID/minimum Framework lanes or final packages. Those full FP-079 obligations and all production gates remain mandatory.
