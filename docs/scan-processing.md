# Opt-in scan correction and reading order

FP-077 has a source implementation profile. Complete automatic document/curve/semantic profiles, actual native/RID/runtime corpora and every production gate remain mandatory. NuGet packing and publication stay blocked.

PdfScanPreprocessing.Process keeps the exact original immutable raster and returns a separate Gray8 raster, captured options, measured scores and complete inverse geometry. The default performs only explicit device-luma conversion; no orientation, skew, denoise, contrast, threshold or dewarp correction is implicit. Opaque BGRA is required; no matte is guessed.

Processing order is reproducible: integer77R+150G+29B luma, optional replicated-edge3x3 median, explicit linear contrast/threshold, explicit dewarping, orientation, then deskew. Nearest-neighbor resampling uses pixel centers and white padding; expanded deskew canvases retain source coverage. Pixel/byte/allocation/time budgets and an explicit cumulative pixel-visit ceiling apply before each stage. Original padding/sample bytes remain available on Original. The retained DPI is the nominal source OCR hint; transformed physical geometry comes from the inverse mapping, not an inferred DPI.

Orientation can be an explicit quarter-turn. Automatic orientation requires an explicitly configured OCR provider and bounded language/model options, compares all four candidate engine mean confidences under the same root context, and enforces the caller's prior best-versus-second margin. Missing scores and insufficient margins reject. Engine confidence and its gap are not correctness probabilities. No orientation model, native runtime or trained data is discovered or downloaded.

Deskew can use an explicit angle or bounded sampled row-projection analysis over a declared extent/increment. Its reported margin compares projection scores, not accuracy. Blank/ambiguous analysis rejects unless the caller explicitly accepts a zero margin; no unreported correction is substituted. SourceSkewDegrees describes the oriented/dewarped intermediate frame, whose correction uses the negative angle.

PdfScanDewarpGrid provides actual bilinear resampling from explicit bounded vertical-curvature control columns. Source X is fixed/increasing per column and Y increases down every column, preventing folds. The source/output dimensions and all controls are caller authority; no page curve or model is inferred. General perspective/horizontal deformation and automatic curve estimation remain pending. Keeping Original does not assert that an explicitly cropped control grid retains all source content in Processed.

PdfScanGeometry maps processed pixel edges through inverse deskew/orientation and the optional dewarp grid into original pixels. MapWord splits a recognized boundary at control-grid crossings and subdivides each quadratic edge until its certified chord error meets the prior pixel tolerance. It retains ordered vertices, a conservative bounding rectangle and the actual error envelope. Padding/out-of-domain words and excessive point counts reject. Apply the original PdfOcrPageFrame.PixelToUser to mapped vertices for PDF coordinates; a nonlinear boundary is not an exact affine text-placement rectangle. Complete curved searchable-text association profiles remain mandatory.

PdfScanLayout analyzes raw immutable word records separately from inferred prose order. Explicit table/form hints retain caller confidence/provenance and keep those words out of prose-column sorting. Optional matching Gray8 pixels identify literal closed2x2-or-larger grids as RuledTableOrForm: their semantics and cell reading order remain unresolved. The analyzer does not silently classify ruled forms as prose columns. Borderless table/form semantics still require explicit authority or a separately qualified semantic profile.

Prose inference uses declared low-density gutters, minimum populations, column limits and line tolerances. Spanning headings/footers partition column bands. Column and within-line direction are explicit. ProseReadingOrder contains source word indices; NonProseWordIndices retains unresolved table/form/grid words in raw engine order. Regions do not assert overall document reading order. All confidence values are declared/heuristic evidence, never calibrated correctness or PDF/UA conformance. Work, rules, regions, words and allocation are bounded.

Recognize combines preprocessing, optional orientation observations, final OCR and layout under one mandatory context. Original images, model selection, temporary workers and budgets stay isolated across jobs. C# and VB consumers preprocess samples and analyze columns on all SDK TFMs.
