# Stream filters and object streams (FP-004)

The managed core implements Flate, LZW, ASCII85, ASCIIHex, RunLength and CCITT fax decoding and encoding. `PdfFilter` captures a decoding name and immutable direct decode parameters. `PdfFilters.Inspect` inspects direct declarations; `Decode` eagerly decodes an immutable stream using the mandatory operation context. `Encode` borrows input and applies the decoding chain in reverse, returning owned read-only encoded bytes. No provider discovery or download occurs.

`PdfSyntaxDocument.DecodeStream(id, revisionIndex, policy, cancellationToken, providers)` resolves indirect filter declarations and supported decode parameters for that revision, then returns immutable `PdfDecodedData` with its own operation report. Data remains valid after the operation ends. Unknown dictionary keys and raw encoded bytes remain available in the original graph. Neither inspection nor decoding executes actions.

Lossless filters accept their standard abbreviated names. DecodeParms arrays must match filter arrays. LZW supports EarlyChange 0/1, clear codes, 9–12 bit code widths and the defined repeated-prefix case. Flate validates the zlib wrapper, block termination, canonical trees, distances and checksum; empty encoding emits an actual final block. ASCII85 validates tuples, zero shorthand and its terminator. Hex preserves an odd final nibble by zero padding. RunLength checks literal/repeat lengths and requires its end marker. Truncation and damaged parameters produce stable fatal Filter diagnostics.

PNG predictors 10–15 and TIFF predictor 2 support 1/2/4/8/16-bit components and arbitrary positive row widths/colors within budgets. Packed padding bits are retained. PNG encoding selects Up for the optimum-choice predictor; this is deterministic and lossless. Encoding requires complete rows; decoding rejects incomplete rows and invalid selectors. Predictor workspaces and decoded segments are charged before allocation. Cumulative expanded-byte limits include intermediate chains, codec state and retained snapshots, so a chain can require more budget than its final byte count. Input/output ownership and context checkpoints apply throughout.

Object streams validate direct N/First fields, unique positive member identities, increasing offsets, generation-zero uncompressed containers, exact member indices and bounded member syntax. They never replace explicit newer cross-reference entries or resurrect freed generations. Stream objects inside an embedded member are rejected. Decode-parameter references have cycle/depth guards; unknown parameter keys are preserved.

Tests include independently encoded fixed/dynamic Flate data, hand-specified ASCII/RunLength/LZW cases, a TIFF-encoded LZW corpus fixture, predictor known answers and packed/16-bit matrices, empty/short/large encoders, chain order, malformed parameters, decompression limits and object-stream faults. The [fixture provenance](../tests/Fluent.Pdf.Contract.Tests/Fixtures/filters/README.md) records original input, encoder identity and digests. These are source regressions, not the complete production corpus or fuzz campaign.

CCITT handles Group 3 one-dimensional/mixed and Group 4 rows, makeup/terminating codes, pass/horizontal/vertical modes, explicit polarity, alignment and end markers. Pixel checks precede image allocation. Independent TIFF decoding verifies encoded output; original independently encoded fixtures verify all decoder modes. See [code facts and provenance](ccitt-code-facts.md). Requested damaged-row repair and extension modes fail explicitly.

DCT, JPX and JBIG2 are routed through an explicitly registered [optional isolated image provider](image-codecs.md). Missing providers reject precisely; no filter returns encoded bytes as decoded samples. The source implementation and independent probes are in progress toward complete codec/profile and native qualification. Image pixels, provider isolation, complete codec evidence, minimum-runtime and final-package consumers remain qualification work. The production readiness manifest stays false, and both candidate creation and publication remain blocked.
