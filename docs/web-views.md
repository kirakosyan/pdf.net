# Trusted application views

FP-048 / queue #62 adds an optional `Fluent.Pdf.Html` source bridge for caller-provisioned Razor/CSHTML, MVC, Blazor, ASPX/WebForms and Windows XAML hosts. This is a trusted application-view boundary, not a compiler or sandbox for untrusted template code. Complete legacy/XAML implementations and real browser/host/runtime/package qualification remain mandatory; the tracking requirement stays Planned.

`PdfWebViews.RenderAsync` captures an explicit `IPdfViewHost` once under the same context as HTML rendering and managed PDF import. Razor/MVC/Blazor/WebForms hosts emit bounded UTF8 HTML; XAML hosts emit bounded complete PDF. Output leases expire when the host returns. The SDK rejects unavailable hosts, empty output, unsupported platform/options, invalid UTF8/PDF, resource overruns and cancellation before exposing a document. Unexpected host errors become redacted `View.HostFailure` diagnostics. No application model, template path, credential or raw exception text enters SDK diagnostics.

HTML capture is limited to 8 MiB, XAML PDF capture to 64 MiB, with the ordinary cumulative operation ceilings. Explicit resource maps and virtual base addresses use the same passive HTML source checks; no URL is fetched by source preparation. JavaScript stays disabled unless enabled explicitly in `PdfHtmlOptions`. Page ceilings apply before returning the imported model. Browser providers remain explicit and must enforce their existing isolated-host/resource/authentication policy.

WebForms requires actual Windows .NET Framework; XAML requires Windows. Other platforms fail with `View.Platform` before rendering. `IsAvailable` is the caller host's explicit prerequisite declaration, not SDK discovery. Dispatcher scheduling, compiled-view resolution, model escaping and any application-side I/O stay within the trusted host implementation. Hosts must propagate the shared cancellation token; arbitrary host code is not preemptively sandboxed by this bridge. Core references no ASP.NET, Blazor or XAML types.

[The executable web sample](../examples/Fluent.Pdf.WebSample/Program.cs) uses real compiled Razor/MVC views and Blazor static HTML rendering on .NET 10. Its regular endpoint requires an explicitly registered real HTML renderer; absence returns 503. Request cancellation reaches the adapter. The sample uses ephemeral data-protection storage. Run `dotnet run --project examples/Fluent.Pdf.WebSample -c Release -- --self-test` to check all three actual view engines through a clearly identified fixture browser boundary. That fixture checks view escaping/import plumbing; it does not qualify browser fidelity. No fixture renderer is registered by the regular endpoint.

The library contract spans all four managed targets. The hosted sample applies to modern .NET; it does not qualify ASPX/WebForms, XAML dispatchers or actual minimum Framework runtimes. Separate real legacy/UI hosts, cancellation/concurrency/ownership cases and full browser/native/production evidence remain required.
