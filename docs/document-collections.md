# Document collections and object XML

FP-100 has source implementations in the optional `Fluent.Pdf.Formats` assembly for all four managed targets. It remains planned and is not production qualified. The core has no new package dependencies. No final SDK package was created or published.

`PdfDocumentCollection.Capture` copies borrowed streams into an immutable collection in enumeration order. It accepts 1–4096 entries, at most 16 MiB per entry and 64 MiB total, subject to the caller's stricter operation budgets. Each item opens an independent read-only stream. Capturing does not identify, parse, convert or execute the bytes. Caller input positions advance and ownership stays with the caller.

`WriteArchive` stages a ZIP with stored payloads, UTF-8 names, fixed timestamps and original order. `WriteArchiveFile` stages in the destination directory and commits atomically. `ReadArchive` returns entries in central-directory order only after all names, local/central headers, extents, expansion, lengths and CRCs pass. It performs no filesystem extraction. The encoded archive is capped at 64 MiB, so header overhead reduces its maximum payload. ZIP64, encryption, non-store/deflate compression, alternate Unicode path identities, links and directories reject. The existing format package profiles remain ASCII; the collection profile explicitly enables strict UTF-8 names.

Names must already be Unicode NFC leaf names, at most 240 UTF-16 code units. The profile rejects separators, traversal, rooted paths, reserved device names, trailing dots/spaces, controls, Unicode format controls, invalid Unicode and platform-ambiguous punctuation. Names must be unique under ordinal case-insensitive comparison, on every OS. These restrictions intentionally reject some names otherwise legal on a particular filesystem. There is no automatic renaming or overwrite resolution.

`Process` uses an explicit immutable `PdfCollectionAdapters` registry, a caller-selected format ID and one shared operation context. Adapters run synchronously in input order with SDK input/output stream leases. Each success returns detached bytes under the original name. An ordinary adapter exception discards that item's partial output and records `Collection.AdapterFailed`; later items continue. Failed items can be retried by processing the immutable source again. Cancellation, latched budget/deadline failures and leaked worker/depth/reservation scopes abort the whole call. Completed batch status does not imply every item succeeded: inspect every outcome. Limits also cap successful output at 16 MiB per item and 64 MiB total; intermediate work consumes the shared budgets.

The registry does not modify process configuration or perform implicit discovery. Its delegates are trusted caller code, **not a sandbox**: arbitrary managed delegates can still change unrelated process state. Enforcing the full isolation acceptance criterion for untrusted format adapters requires a reviewed worker integration and remains open. Independent calls can share immutable input bytes; callers must synchronize any mutable state inside their own adapters. The SDK neither copies nor claims to isolate callback closures.

## Object XML profile

`PdfObjectXml.Export` parses an unsigned, unencrypted PDF under the operation context and emits the proprietary version-one vocabulary `urn:fluent-pdf:objects:1`. The `pdf` root declares `version="1"` and `pdfVersion`. Its first child is a `trailer` containing one dictionary, followed by `object` children with unique active `number` and `generation` attributes and exactly one typed value each.

Values are `null`, `boolean`, `number`, `name`, `string`, `reference`, `array`, `dictionary` or `stream`. Decimal tokens remain exact; names and dictionary `entry` keys encode their byte values as canonical base64, and strings encode uninterpreted bytes. References retain number/generation, bounded to object numbers 0–1,000,000 and generations 0–65,535. Active object definitions require nonzero unique numbers. Streams contain dictionary entries followed by one final base64 `data` child with opaque encoded bytes. Stream lengths are regenerated. Indirect references are not followed recursively by XML conversion.

`Import` rejects unknown elements/attributes, duplicates, noncanonical base64, DTDs, external entities, processing instructions, comments, unexpected container text and unsupported versions. It validates and stages the entire new PDF before writing to the borrowed destination. Caller-stream I/O failures may leave partial output. XML input/output is capped at 16 MiB; PDF staging is capped at 64 MiB and remains subject to operation budgets. Ordinary processing stays offline.

Interchange preserves the active typed graph, not original file bytes. It omits prior revisions, free xref entries and object/xref compression containers, regenerates offsets and writes one full revision. Every successful operation reports `Interchange.ActiveGraph`. Encrypted trailers and signature byte ranges reject; this API cannot preserve signatures, encryption or audit history. It does not decode content streams or execute document actions. No interoperability with another vendor's XML vocabulary is claimed.

## Source evidence and remaining gates

The compiled C# and Visual Basic `CollectionRoundTrip` consumers archive object XML and reconstruct a PDF. Contract tests exercise Unicode/order, collisions/traversal, device names, malformed UTF-8, symlinks, CRC/header corruption, atomic-file failure, finite entry/input limits, individual recovery, instance registry ownership, leased streams, cancellation, swallowed latched failures, leaked scopes, exact value tokens, xref stream conversion, unknown XML, entities and protected-object rejection. `eng/verify-collection-fixtures.py` independently inspects ZIP CRC/name/payload/metadata and XML tokens with Python's standard library; its optional reader mode compares reconstructed PDF text and 144 DPI pixels using pypdf and MuPDF.

See [the exact source evidence](evidence/FP-100-source.json). Actual minimum Framework 4.7.2, full runtime/RID coverage, untrusted adapter isolation, broad adversarial/fuzz/endurance corpora, complete conformance/fidelity and exact final package consumers remain unqualified. #93 is still skipped at the user's request and remains a mandatory release gate. All production requirements and publication blocking remain unchanged.
