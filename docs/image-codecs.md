The optional `Fluent.Pdf.Codecs` assembly supplies `IsolatedImageCodecProvider` for DCT, JPX and JBIG2 stream filters. The core stays independent of image/native packages. Registration is explicit, and every operation uses the SDK context, expiring stream leases and bounded output sink.

The provider requires a caller-owned, offline deployment of the original worker and `fluent-pdf-codecs` native bridge. It accepts only ABI `fluent-pdf-codecs-1`, version `1.0.0`, the OS-native worker architecture, pinned file lengths/hashes and explicit in-process thread permission. It never loads the codec into the application process. Source builds cover Windows, Linux and macOS x64/ARM64. Actual runtime execution and remaining platform failures are CI evidence, not inferred from this inventory.

Header inspection checks JPEG SOF dimensions/precision, JP2 box and codestream SIZ bounds/terminal marker, and JBIG2 page information before a pixel decoder starts. JPX tile-component counts charge the object budget before decoding. The SDK checks the returned geometry against the PDF dictionary and charges pixels before invoking the decoder. Successful output must have exactly the packed, byte-aligned image extent.

Every codec call charges the complete configured process memory envelope to the operation's expanded-byte budget before launching third-party code. This is deliberately conservative: an explicit one-GiB process envelope needs more than one GiB of remaining operation budget, including transport and retained sample buffers. Independent calls accumulate charges. The child receives a bounded workspace policy, shares an object reservation with its parent, reports consumed objects, and applies the JPEG 2000 library's pixel/memory/tile limits. Native process memory, CPU and wall-clock limits remain in force. Cancellation destroys the job; there is no unrestricted fallback.

DCT supports eight-bit grayscale, RGB and CMYK baseline, extended-sequential and progressive JPEG processes. `ColorTransform` is -1 (marker/default), 0 (direct components), or 1 (YCbCr/YCCK). Encoding quality is 1–100, default 90; requesting DCT explicitly produces an informational quantization diagnostic. Decoder errors and damage warnings reject the whole output. Chroma interpolation differs between the chosen library and other valid JPEG decoders and still requires production fidelity assessment.

JPX encoding is reversible. Decoding preserves one to four unsigned, equally precise 1–16-bit, full-resolution components without applying embedded color conversion; image color spaces, alpha and profiles belong to the image/color layers. Signed, mixed-precision or subsampled component representations currently reject with `Codec.UnsupportedProfile`. JBIG2 decoding uses the optional filter implementation, including explicit decoded globals; encoding is original lossless MMR generic-region construction. PDF sample bytes use 0 for black and 1 for white; unused packed padding is codec-defined and is not a pixel. Unknown or inapplicable parameters reject with `Codec.Parameters`.

The managed contracts and independent codec probes establish source behavior. They do not complete the security audit, full codec profile corpus, endurance, fuzzing, minimum-runtime, exact-package or final native-artifact qualification. All stable-release requirements remain mandatory, and candidate creation and NuGet publication stay blocked.
