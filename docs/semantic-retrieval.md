# Explicit chunks and scoped retrieval

The optional `Fluent.Pdf.Intelligence` assembly provides `PdfSemanticChunks.Capture`, `PdfJsonEmbeddingProvider`, `IPdfVectorStore`, `PdfMemoryVectorStore` and `PdfVectorRetrieval`. These are original managed implementations with no additional runtime packages, default models, HTTP clients, credentials, model downloads or shared payload cache. Core remains independent of model and store integrations.

Capture requires explicit ascending page indices. It retains raw mapped character text in operator execution order, including whitespace already present in source clusters. Concatenating primary chunks for each selected page exactly reconstructs that page's captured raw text. No geometric separators, overlap or ActualText replacement are inserted. The byte ceiling never splits a Unicode cluster, surrogate pair or CRLF pair; an indivisible cluster exceeding the limit rejects. Line ends and source whitespace are preferred boundaries. Empty pages are recorded without invented text. Hidden layers are excluded; nonpainting text is excluded unless explicitly enabled. Text mapping does not prove visible ink: occlusion, white text, transparency, malicious mappings and clipping still require a separately qualified inspection/redaction workflow.

Optional `PdfTableExtractionOptions` selects the existing ruled or borderless inference profile under the same capture context. Chunks cannot cross membership transitions between prose and an inferred table. Long tables may span multiple chunks carrying the same page-local table identity. No candidate is reported explicitly. Table continuation is a separate operation and is rejected as a chunk option. Geometry/table inference is not author-confirmed semantic structure, logical reading order or accessibility qualification. Complete tagged semantic chunking and representative corpus qualification remain mandatory FP-080 work.

Each immutable chunk records page index, exact UTF16 source offset, UTF8 text hash/length and original character mapping confidence, operator index, displayed advance quad and native PDF user quad. Detached character records omit internal source-stream references. The capture hash binds the complete PDF revision, selected pages, inference/options profile and exact chunk boundaries/content. `MaximumUtf8Bytes` records the `utf8-bytes/v1` boundary profile, not an asserted count for an arbitrary model tokenizer. The embedding adapter separately reserves the complete serialized wire using a caller-configured byte-token upper bound; that bound requires qualification against the exact backend/tokenizer.

The trusted host creates `PdfRetrievalScope` from its tenant/document identities and the capture's complete `DocumentSha256`. It supplies an authenticated principal and `PdfRetrievalPermissions` containing host policy/version, writer and explicit readers. These values carry application permission provenance; they do not authenticate identities or recover permission authority from an already decrypted PDF. The host must establish extraction authority before capture and must never accept a document/model-selected principal or ACL. Scope components are compared separately with an unambiguous internal key.

Indexing authorizes the exact scope before accessing model metadata, preparing a request or sending text. Only the explicitly configured memory-store administrator can create an absent index. Subsequent writers must match the authoritative stored writer/administrator and preserve the stored ACL. Reader access is checked before query embedding and again during search. A different tenant, document, revision, model version, provider, endpoint or dimension cannot reuse an index. There is no cross-document embedding cache. Removal revokes a complete generation; ordinary readers/writers cannot recreate a removed scope. Hosts can then recreate it through their administrative lifecycle with reviewed permissions.

`PdfJsonEmbeddingProvider` uses an explicit fixed-endpoint caller transport and original `model`/`input`/`dimensions`/`encoding_format:float` JSON. Remote services require per-operation exact HTTPS-origin consent. Local services use a literal loopback endpoint. The provider performs no retry, follow-up or response-directed request. It validates exact returned model, unique contiguous response indices, batch count, configured dimension, finite nonzero vectors and coherent reported input usage. Its strict decimal JSON number profile rejects precision loss, nonfinite numbers, nonzero underflow and numbers outside the parser's exact decimal range; other floating-point wire profiles need separately qualified adapters. The SDK associates the owned transport response with its exact request binding; this protocol does not require a backend hash echo. Borrowed request leases expire at transport return, and owned responses are disposed even when cancellation arrives immediately after return.

Token/context and explicitly configured-rate cost reservations precede model dispatch. Reported usage cannot exceed the reservation. These controls do not verify service billing, actual tokenizer behavior, model identity beyond the declared protocol, service retention or caller transport security. Transport implementations must enforce their own fixed endpoint, origin/IP/TLS/credential/redirect/cancellation policy. No document action, returned instruction or model text grants SDK authority.

The memory store atomically swaps complete immutable indexes with generation checks. Failed embedding, cancellation, capacity rejection or a stale generation leaves the prior index intact. A concurrent replacement/removal rejects stale queries before results return. Scoring uses scaled compensated cosine sums, handles extreme finite vectors, and breaks equal-score ties by original chunk order. Top-k, documents, records and estimated retained-index bytes are finite; operation budgets separately charge active snapshots and work. The resident estimate is conservative accounting for retained index data, not a CLR heap-size guarantee. Independent jobs may share the synchronized memory store; provider/transport concurrency remains caller responsibility. External stores must implement the same authoritative ACL, generation, scope, dimension, cancellation and atomic-commit contracts, with separately explicit remote store configuration.

Capture, index and search are separate explicit operation boundaries. Capture shares parse/extraction/inference/chunk budgets. Each index/search shares authorization, preparation, dispatch and commit/scoring budgets. C# and VB consumers execute `ChunkSelectedPage`. Original fixtures cover text/table/Unicode boundaries, recorded retrieval, cross-scope isolation, malformed responses, quota/cancellation cleanup, revocation and concurrent queries/writes. An independent PDF reader checks mapped glyph text separately from geometric whitespace, and an independent cosine calculation checks rankings. The three hand-labeled queries use recorded feature vectors; they do not establish live embedding relevance.

All complete feature, real model/store/transport/tokenizer, tagged semantics, representative relevance/security/resource/endurance, actual runtime/RID/minimum Framework and exact final-package qualification obligations remain mandatory. `docs/evidence/FP-080-source.json` records the exact checked checkpoint without closing FP-080 or authorizing package publication.
