# Optional-content layers

FP-024 has an original managed source profile on all four core frameworks. `PdfLayers.Inspect` captures registered OCG identities, Unicode names and raw default/alternate configurations without applying usage, opening a UI or executing actions. Names need not be unique. `AddGroup`/`EditGroup` preserve unrelated source group data; intent authoring supports View/Design and usage authoring supports explicit View, Print and Export states. Usage fields affect state only through configuration AS applications.

`SetConfiguration` validates registered group references, ON/OFF, standard order trees, intents, radio/locked lists, display settings and supported usage applications. The default BaseState is ON; alternate configurations may use OFF or Unchanged. `SelectConfiguration` resolves an alternate configuration and explicit usage into the initial view's ON/OFF states, retaining inherited presentation order. `BindXObject` clones a selected page's Form/image resource and attaches an OCG reference or OCMD. C#/VB `WriteLayerPdf` binds a private canvas Form to a hidden group.

`IsVisible` evaluates the four standard OCMD policies and nested And/Or/Not VE expressions with bounded depth/work and cycle detection. Empty/null/deleted OCMD group memberships have no visibility effect. Disjoint intents do not hide content. Multiple matching usage applications combine their recommendations; an omitted AS OCGs array affects no groups. View applies initial viewer usage. Print/Export first apply that viewing state and then the matching temporary event. Configured uses only the configured states, as a stand-alone printing/aggregation application does. Zoom/language/user-dependent applications require additional explicit environmental profiles and reject when requested. Actions never alter state implicitly.

`Flatten` stages a full rewrite for a selected configuration/event. It processes page content, nested Form/image resources and annotation appearances; drops hidden XObject/image invocations, hidden annotations and supported hidden text; removes optional markers and group/property references; and prunes old/unreachable graph objects and revisions. Ordinary page extraction retains valid group/configuration relationships. Independent rendering verifies emitted initial-view and extraction behavior; an SDK renderer is still owned by FP-040.

Hidden painting still affects graphics state in PDF. Flattening therefore retains color, transforms, clipping and other state operations and replaces hidden path painting with path termination. Text position resets permit removal of hidden text before later visible text. Cases whose removed text advance, inherited text mode, text clipping or replacement/alternate text cannot yet be preserved reject before commit. The current profile also rejects Type 3 glyphs, tiling patterns, soft masks, interactive/structured documents, layer-state actions and nonstandard surviving group relationships that require further ownership/state work. These missing profiles remain required work; this source profile is not full requirement or production qualification.

Flattening is not redaction: retained state/path geometry and unrelated semantic copies are not a privacy erasure guarantee. Strict mode does not silently rasterize, drop a state dependency or widen a resource limit. Shared cancellation, budgets, immutable snapshots, borrowed stream ownership, signature invalidation permission and atomic saving apply. Full layer/renderer/standards corpora, actual minimum runtimes, exact final package consumers and all production gates remain mandatory. NuGet packing and publication stay blocked.
