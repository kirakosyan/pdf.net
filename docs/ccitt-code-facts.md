# CCITT code facts and original probes

The fixed terminating/makeup code tables are ITU-T T.4 coding facts. They were observed independently using original two-row constant-color bitmaps with Pillow 12.3.0 and libtiff 4.7.1. The first row's Group 3 payload lies between its two EOL markers. White terminating runs 1–63 are direct observations; the common prefix of black runs yields white zero. The common suffix of black makeup runs yields black zero; removing these known terminating codes isolates makeup values 64–2560. Known white/black zero/one codes were checked before generating the tables.

[ccitt.json](../specs/codec-facts/ccitt.json) records the facts and encoder identity. Its SHA-256 is `d4be36e1c933880692c500c0cb76da14574e5769b7cad3beb661389806951c3a`. [PdfCcittCodes.cs](../src/Fluent.Pdf/Syntax/PdfCcittCodes.cs) contains those code facts. The parser, geometry, bit transport and encoder bodies are original; no reference implementation body was copied.

The original bitonal corpus contains shifting transitions, merged runs, checkerboards, blank/full rows and long makeup runs. Independent TIFF encoding produced Group 3 one-dimensional/mixed/fill-aligned and Group 4 strip bytes. Its [manifest](../tests/Fluent.Pdf.Contract.Tests/Fixtures/filters/ccitt/manifest.json) records dimensions, options and digests; raw sample arrays are original MIT-licensed input. These data fixtures are not third-party executables. Source tests compare actual decoded samples, not output regenerated from this decoder.

The implementation uses bounded row state, transition arrays, pixel accounting and checkpoints. Group 4 and mixed Group 3 encoding currently choose horizontal two-dimensional modes; output is lossless, with compression/performance qualification still pending. Unsupported extension modes and requested damaged-row recovery fail explicitly. Full conformance, mutation/fuzz, independent output interoperability and exact-package qualification remain required.
