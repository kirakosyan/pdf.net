# XPS/OpenXPS raster-page source profile

`PdfXps.WriteRasterPages` writes original XPS2005 or OpenXPS1.0 OPC fixed-layout packages. The caller explicitly selects the namespace/version, language, rendering provider/options and 1–512 source pages in exact order, including duplicates. Each page becomes a PNG image brush on an explicit page rectangle. The writer uses integral96-DPI fixed-page units for the tested reader interoperability profile. Page dimensions that are exact multiples of0.75 points retain their size. Fractional units require rounding up: strict mode rejects before raster capture; explicit permissive mode reports `Xps.PageGeometryQuantized` because physical dimensions and image placement change. Fractional-unit interoperability remains mandatory and pending. Generated PNG density metadata is removed so image-space units use the standard96-DPI default without a second density scale. Raster sample data is unchanged. Every page reports `Xps.RasterPage`; no editable glyph/vector or semantic reconstruction is claimed.

The generated package uses canonical sequence/document/page/image names, exact main content types, root fixed-representation relationships and per-page required-resource relationships. Internal references are resolved relative to their owning parts. Output stages before caller writes, with64 MiB package/16 MiB part bounds. All parsing, raster capture, encoding and import share the caller operation context and cancellation/deadline/object/pixel/byte limits. Caller streams/providers remain caller-owned.

`ImportRasterPages` validates the exact requested format/namespace and canonical main sequence, then preserves fixed-document/page order and physical geometry in an independent PDF. The closed input profile accepts a single canonical page-rectangle path with an absolute untiled full-image PNG brush, and validates its required-resource relationship, full viewbox and viewport before decoding. PNG alpha and decoded color samples are retained by the managed image pipeline. Source image density is considered when validating external brush image-space geometry. It does not infer missing geometry or substitute an empty page.

Package traversal, external/unsafe URIs, duplicate/case-aliased identities, header/descriptor/CRC conflicts and excessive expansion reject through the common ZIP/OPC boundary. XML has no DTD, stylesheet, external entity or action execution. Print-ticket content types/relationships report `Xps.PrintTicketUnsupported`; unsupported glyphs, resource dictionaries, vector/effect constructs and cropped/partial brushes report explicit failures. Relationship targets must exist. No Windows UI, GDI/XPS desktop session, browser, font discovery or runtime native download is introduced.

Full XPS/OpenXPS vector/glyph/resource-dictionary reconstruction, font obfuscation/color/print-ticket semantics, broader legal package/layout forms and complete host/package production qualification remain mandatory for FP-059, which stays Planned. Source tests cover both namespaces, ordering, exact geometry/samples, relationship/version identity, unsafe resources, unsupported constructs, budgets and cancellation. Independent XPS reader rendering is recorded for controlled outputs; those fixtures do not qualify the complete standards.

Independent GhostXPS10.05.1 reads both controlled versions with matching integral page geometry, order and pixels. Its dedicated XPS interpreter is used explicitly; an image-archive fallback is not counted as XPS support. Original fractional-page reader failures are retained in `artifacts/contracts/queue-61-80/xps/fractional-investigation`. Reader build and configuration provenance is recorded in `eng/format-checks/ghostxps-reader.json`.
